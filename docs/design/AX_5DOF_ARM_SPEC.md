# AX 자체 5축 로봇팔 설계 사양안

작성일: 2026-10-21. 상태: **v0.1 모델 설정 반영, 동적 성능 미검증**. 적용 대상은 실제 기구가 없는 가상 AX 로봇이다. 이 문서는 실제 5축 로봇을 참고한 AX 자체 설계이며 제조사 정격을 이전한 것이 아니다.

2026-10-22 결정에 따라 이 팔은 협업 그룹의 **robot_1**(흡착 팔 로봇)에 해당한다. robot_2(적재함 운송 로봇)는 팔이 없다. 그룹 운반 흐름과 계약은 [통합 상세설계](DETAILED_DESIGN.md) 3·7·9절을 따른다. 아래의 결정 사항도 현재 코드 구현이나 검증 완료를 뜻하지 않는다.

## 현재 적용 상태

| 항목 | 반영 내용 |
|---|---|
| 링크 질량 | 아래 질량 예산을 URDF에 반영. 받침·기둥·팔·공통 어댑터 합계 16.2 kg |
| 무게중심·관성 | 모터·하우징·기둥 튜브·차체 하부 질량의 가상 배분으로 재계산. 부품별 충돌 상자 적용. [보완 결과](../validation/PHYSICAL_PROPERTIES_REVIEW.md) 참고 |
| 관절 속도 | J1~J5 URDF velocity: 0.35 / 0.50 / 0.50 / 0.70 / 0.70 rad/s |
| 가속도 | `src/ax_description/config/arm_joint_limits.yaml`에 계획용 설정 저장. 현재 ros2_control 경로(`arm_controller`, `enforce_command_limits` 미설정)는 이 파일을 읽지 않으며 실행 중 가속도를 강제하지 않음 |
| 관절 위치·회전축·시각 외형 | 기존 5축 구조·범위 유지. 충돌 형상은 부품별 상자로 보완 |
| effort·PID | 어깨·팔꿈치·손목 effort는 정적 토크 계산으로 정한 개발용 잠정값(6.1절, 2026-10-25 반영). 기둥 yaw·말단 회전 effort와 PID·이득은 기존 미검증 설정 유지 |
| 상자 2 kg·말단 3.5 kg·TCP 속도·반복 정밀도 | 설계 목표로 유지. 시험 통과나 제어기 구현 완료를 뜻하지 않음 |

확인: 3개 패키지 빌드, 집게 4종 Xacro·URDF 검사, 질량 합계·관성 재계산·관성 양의 정부호 및 삼각 부등식·속도 설정 일치·기존 형상 유지 통과. [초기 질량·속도 적용 기록](../evidence/model/arm_spec_v01/model_checks.json)은 무게중심 보완 전 결과다. 최신 부품별 질량 특성과 정적 지지 여유는 [보완 결과](../validation/PHYSICAL_PROPERTIES_REVIEW.md)를 참고한다. Gazebo 하중·추종·동적 전도 시험은 미실시다. RViz 수동 슬라이더는 물리 속도·가속도 제한 시험 도구가 아니다.

## 1. 참고 모델과 적용 원칙

참고 모델은 UFACTORY xArm 5 Lite다. 아래 제조사 값은 [UFACTORY 공식 비교 문서](https://docs.supportarticle.ufactory.cc/support_articles/hardware/the-difference-between-ufactory-xarm5-xarm6-and-xarm7.html)를 2026-10-21에 확인한 값이다.

| 항목 | 실제 xArm 5 Lite | AX에 활용하는 방법 |
|---|---|---|
| 자유도 | 5축 | 기둥 회전·어깨·팔꿈치·손목·말단 회전의 5축 구성 참고 |
| 도달 거리 | 700 mm | AX는 링크 길이가 달라 그대로 적용하지 않음 |
| 가반하중 | 3 kg | 소형 상자 취급 목표의 참고값. AX 정격으로 이전하지 않음 |
| 본체 질량 | 11.2 kg | 질량 규모를 비교하는 자료. AX의 기둥·받침과 포함 범위가 다름 |
| 최대 관절 속도 | 180°/s | AX는 저속 운반 시험부터 시작 |
| Cartesian 동작 특성 | 문서상 유효한 유연 자유도는 x/y/z/yaw의 4개 | 상자를 위에서 집고 내려놓는 작업을 우선 |

제조사 문서는 xArm5의 Cartesian 이동에 말단 면과 베이스 면의 평행 조건을 설명한다. AX는 별도의 관절 배치이므로 이 동작 제약이나 IK를 그대로 가져오지 않는다. AX 역시 5축이므로 임의의 위치 3개와 자세 3개를 모두 독립적으로 지정할 수 있다고 가정하지 않는다. AX의 실제 제약은 자체 FK·Jacobian·IK로 확인한다.

아래 수치는 **AX 자체 설계 목표**다. 제조사 수치에서 비례 환산하거나 성능을 입증한 값이 아니다.

| 기준 접근 | 상자 윗면을 향해 수직 하강 | 도달 가능성과 자기 충돌 통과 후 실행 |

시험 횟수는 개발 중 확인 3회와 최종 조건별 평가 10회를 구분한다. 위 10회 기준은 최종 평가에 적용한다.

말단 질량 목표는 허용 토크나 차체 안정성이 확인되기 전까지 정격으로 표시하지 않는다. 긴 공구 또는 무게중심이 치우친 상자는 질량이 같아도 별도 시험한다.

## 3. 현재 형상과 작업 범위

기준 파일: `src/ax_description/urdf/ax.urdf.xacro`. 메시의 mm 가정과 현재 관절 원점을 사용한다.

| 구간 | 현재 관절 원점 사이 벡터 (m) | 원점 간 거리 |
|---|---|---|
| 어깨 → 팔꿈치 | (0.132, 0, 0.560) | 약 575 mm |
| 팔꿈치 → 손목 | (0.090, 0.455, -0.440) | 약 639 mm |
| 손목 → 공통 어댑터 | (0, 0, -0.274) | 274 mm |

첫 두 구간의 3차원 거리 합은 약 1,215 mm지만, 관절축·각도 제한·공구·충돌에 따라 실제 작업 영역은 달라진다. 이 값을 제조사 방식의 도달 거리나 수평 작업 반경으로 표기하지 않는다. 현재 어깨·팔꿈치·손목의 축이 모두 로컬 X인 점도 포함해 FK로 계산해야 한다.

현재 기본 조립 자세에서 어깨의 지상 높이는 바퀴 외곽 기준 약 1.462 m다. 새 AX_1 메시의 짧아진 기둥·팔 위치를 반영한 값이다. 기둥 yaw를 pitch 관절로 간주하거나 기둥 높이를 팔 길이에 더하면 안 된다. 이전 primitive 공구 기준 계산에서 바닥 접근 부족이 확인되었으며, 이번 문서 작성으로 해결된 것은 아니다.

### 3.1 기구·무게중심 수정 계획 — 새 메시 반영, 작업 공간 미검증

- 팔 조립체를 원본 대비 X=-177 mm, Y=-185 mm 옮겨 기둥 회전축을 차체 X/Y 중심에 배치했다. 전체 COM의 중앙화와 자세별 안정성은 별도 검사 대상이다.
- 팔이 걸리는 부위의 공간·간격을 넓혀 팔이 더 아래로 내려갈 수 있는 가동 공간을 확보한다.
- 새 `AX_1.obj`의 파츠·manifest·visual 원점·관절 기준점과 생성 collision·COM·관성을 반영했다. 질량 예산과 관절 제한은 유지했다. 작업 공간 확대·무게중심 개선의 달성 여부는 아직 검증되지 않았으며, 추가 수정 시에도 자산 버전·mm 단위·관절·물리 특성을 함께 관리한다.

검증 순서:

```text
메시·배치 수정
→ 충돌·질량 특성 반영
→ 작업대·적재함·인계 위치 후보 설정
→ 도달·접근·후퇴·충돌 검사
→ 정적 토크·무게중심 검사
→ 후보 조정 및 확정
→ Gazebo 동적 검증
```

기본 자세만 중앙화하지 않고 주행 자세·집기 자세·인계 자세를 비교한다. 작업대 높이·위치, 상자 크기·질량, robot_2 적재함 크기·높이, 인계 상대 위치·허용 오차는 이 검증 결과로 정하며 현재 미정이다.

초기 검증은 도달 가능한 높이의 작업대와 로봇 적재 위치를 사용한다. 작업대 높이와 작업 반경은 공구별 IK·충돌 검사 후 좌표로 확정한다. 바닥에 놓인 상자의 윗면을 잡는 경우에는 바닥 높이 0 m가 아니라 **상자 높이의 접촉면과 접근 경로**를 검사한다. 바닥 작업이 필수라면 어깨 장착 높이를 낮추는 안과 팔 링크 길이 변경안을 먼저 비교하고, 기둥 승강은 초기 사양에 넣지 않는다.

## 4. 관절별 초기 운용 설정안

위치 범위는 현재 AX 범위를 유지한다. 제조사 기준 자세와 AX의 메시 조립 자세가 달라 xArm5의 관절 한계를 그대로 복사하지 않는다. 아래 속도는 URDF에 반영했으며 가속도는 계획용 YAML에 저장했다. 가속도를 실행 중 적용하려면 해당 파일을 사용하는 궤적 생성·제어기가 필요하다.

| 축 | URDF 관절 | 기능 | 현재 위치 범위 (deg) | 제안 최대 속도 (rad/s) | 제안 최대 가속도 (rad/s²) |
|---|---|---|---|---|---|
| J1 | `column_yaw_joint` | 중앙 원통과 팔 전체 수평 회전 | 약 -180~180 | 0.35 | 0.50 |
| J2 | `shoulder_joint` | 어깨 굽힘 | 약 -90~90 | 0.50 | 0.50 |
| J3 | `elbow_joint` | 팔꿈치 굽힘 | 약 -114.6~114.6 | 0.50 | 0.70 |
| J4 | `wrist_joint` | 손목 굽힘 | 약 -90~90 | 0.70 | 1.00 |
| J5 | `gripper_rotation_joint` | 말단 회전 | 약 -180~180 | 0.70 | 1.00 |

현재 범위 전체가 자기 충돌 없이 사용 가능하다는 의미는 아니다. 충돌 검사로 필요하면 범위를 줄인다. 가속도는 URDF 기본 limit 항목이 아니므로 궤적 생성·제어 설정에서 관리한다. 최종 접근에서는 TCP 속도 제한과 관절 한계를 동시에 만족하도록 시간 배율을 조정한다.

## 5. 질량 예산과 관성 산정

아래 질량은 형상과 동적 시험을 구체화하기 위한 **초기 배분값**으로 URDF에 반영했다. 실제 xArm5 링크 질량이 아니며, 메시 부피로 산출한 값도 아니다. 후속 보완에서 모터·하우징·기둥 중공 튜브·차체 하부 질량을 가상으로 배분하고 무게중심과 전체 관성 텐서를 다시 계산했다. 가정과 수치는 [보완 결과](../validation/PHYSICAL_PROPERTIES_REVIEW.md), `physical_properties.json`, 생성기 `tools/generate_physical_properties.py`에 기록했다. 실제 내부 구조의 실측값은 아니다.

| 링크 | 적용 전 임시 질량 (kg) | AX 적용 질량 (kg) |
|---|---|---|
| `arm_mount_link` 고정 받침 | 0.6 | 3.0 |
| `column_link` 회전 기둥 | 0.4 | 4.0 |
| `arm_rotating_base_link` 상단 연결부 | 0.6 | 1.0 |
| `upper_arm_link` | 1.5 | 4.0 |
| `forearm_link` | 1.0 | 3.0 |
| `wrist_link` | 0.3 | 1.0 |
| `gripper_base_link` 공통 어댑터 | 0.2 | 0.2 |
| 합계: 받침·기둥·팔·공통 어댑터 | 4.6 | 16.2 |

공구·상자는 위 합계에서 제외한다. 현재 가상 공구 질량은 넓은 평행 집게 1.3 kg, 가상 4컵 흡착 헤드 0.56 kg으로 공구 예산 안에 있다. 기준 공구 EPick은 원본 description에 질량 특성이 없으므로 제품 질량 특성과 컵 구성을 확정한 뒤 공구 예산·COM·토크 계산에 반영한다. Robotiq은 해당 URDF의 실제 질량 합계로 따로 계산한다.

메시가 폐곡면이면 가정한 재질·밀도와 내부 구조를 명시해 질량 특성을 산출한다. 폐곡면이 아니거나 내부 구조가 없으면 상자·원통의 복합체로 근사하고 근사 방법을 기록한다. 무게중심은 링크 좌표계로 변환하며, 관성 텐서는 해당 무게중심 기준으로 계산한다. 질량만 바꾸고 기존 작은 관성을 유지하지 않는다.

## 6. 모터 토크와 제어값 결정

현재 effort는 J1~J5 순서로 10 / 100 / 65 / 25 / 5 N·m다(2026-10-25에 어깨·팔꿈치·손목을 기존 20 / 15 / 5에서 6.1절 후보로 바꿈). 이 값은 개발용 잠정값이며 목표 하중에 대해 검증된 모터 사양이나 실물 정격이 아니다. 예를 들어 **수평 모멘트암 1.2 m에 상자 2 kg만 걸리는 가정**에서도 중력 토크는 `2 × 9.81 × 1.2 ≈ 23.5 N·m`다. 이는 공구·팔 자체 무게와 가속도 부하를 제외한 설명용 계산이며, 현재 제한 안에서 실제 도달하는 자세의 토크 계산은 아니다.

토크는 다음 순서로 확정한다.

1. 링크 질량·무게중심·관성과 실제 사용할 자세·궤적을 정한다.
2. 각 자세에서 중력 토크를 계산하고, 궤적의 관성·마찰 항을 포함한 역동역학으로 관절별 필요 토크를 구한다.
3. 연속 유지 토크와 순간 최대 토크를 나누고, 초기 설계 여유율 1.5를 적용해 시험한다. 이 계수는 제조사 보증이나 인증 기준이 아니다.
4. 제어기의 출력 제한·속도·가속도·PID 및 damping을 조정하고, 실제 시뮬레이션 effort와 추종 오차로 확인한다.

`effort` 수치만 늘려서 목표 가반하중을 달성했다고 판정하지 않는다. 현재 ros2_control 구성(gz_ros2_control 1.2.20)은 위치 명령을 Gazebo 관절 속도 명령으로 적용하며 URDF effort가 출력 상한이다. 이전 미검증 effort(어깨 20·팔꿈치 15 N·m)는 무부하 작업 자세의 어깨 정적 중력 토크(대표 자세 23.8~38.7 N·m)보다 작아 어깨가 하한으로 처졌고, 현재 잠정값에서는 무부하 대표 자세가 정착·유지된다(6.2절). 하한에 닿은 관절이 복귀하지 못하는 문제는 effort와 별개다([인터페이스](../guides/INTERFACES.md)). `joint_states` effort는 Gazebo 관절 전달 렌치의 축 성분이며 관절 한계 반력을 포함할 수 있어 모터 토크로 그대로 쓰지 않는다. 관절별 토크 정격은 이 계산 전까지 **미확정**으로 둔다.

한계는 다음과 같다.

- 여유율 1.5는 이 절의 초기 설계 계수이며 제조사 보증·인증 기준이 아니다. 마찰·감속기 효율·궤적 역동역학·충격을 대신하지 않는다.
- 모터 출력을 키우면 모터 질량이 늘 수 있으므로, 질량 예산·COM·토크 계산을 다시 해야 한다.
- 정적 계산은 동적 성능이나 파지 성공을 보장하지 않는다.

제어 방식 검토(이번 단계에서 전환하지 않음):

- 현재 gz_ros2_control은 위치 오차를 Gazebo 관절 속도 명령으로 바꾸고, effort 상한 안에서 구속력으로 그 속도를 맞춘다.
- 상한이 충분하면 중력은 이 구속력이 받아 주므로, 시뮬레이션의 정적 유지에 별도 중력 보상이 필요하지 않다. effort 범위 안의 L1·L2 자세에서 오차 0.000 rad가 측정됐다.
- 다만 effort를 크게 주는 것만으로 충분하다고 보지 않는다.
  - effort는 구속력이며 모터 토크·전류 모델이 아니다.
  - 상한을 키우면 상자·작업대와 닿을 때의 힘도 그만큼 커진다. `self_collide`는 설정하지 않았다.
  - 오차 × 10 s⁻¹ 속도 명령이 URDF velocity로 제한되는지 확인하지 않았다. 하한 복귀처럼 오차가 큰 상황에서 급한 동작이 나올 수 있다.
  - 가속도·TCP 속도는 강제되지 않는다.
- effort(토크) 명령 인터페이스로 바꾸면 중력 보상 피드포워드와 PID 조정이 필요하다.

별도 문제로 구분한다.

- **토크 부족:** 위 표의 내용이다.
- **관절 한계 반력:** 하한에 닿은 상태의 effort이며 요구 토크 근거로 쓰지 않는다.
- **차체 정적 안정성:** 위 9개 작업 자세의 전체 COM은 2 kg 가정에서도 지지 사각형 안쪽 여유가 primitive 0.114 m, suction 0.103 m 이상이다(최소는 P1). 그러나 전 가동 범위 샘플에는 지지 영역을 벗어나는 자세가 있다([물리 검사](../validation/PHYSICAL_PROPERTIES_REVIEW.md)). 차체 질량을 임의로 늘려 해결하지 않는다.

### 6.2 후보 적용 후 검증 계획

조건은 단일 AX_1, 격리 headless 실행, 바닥 수평이다. 현재 effort와 후보 effort를 같은 조건에서 비교한다. 개발용 정착 기준은 관절 오차 0.02 rad 이하이면서 속도 절댓값 0.01 rad/s 미만을 1 s 유지하는 것이며, 관절별 정착과 팔 전체(5축 모두) 정착을 따로 기록한다. 관측값은 `joint_states`의 위치·속도·effort, action 결과, 정착 시간, 최대 속도·오버슈트다.

| 시험 | 자세·조건 | 시간 | 확인 |
|---|---|---|---|
| 목표 추종 | P0~P3, L1·L2, `verify_handoff.py` 목표. 자세별 새 실행, 4 s 궤적, 각 3회 | 자세당 15 s | 관절별·팔 전체 정착 시간, 최종 오차, `verify_handoff.py` 종료 코드(현재 2, 어깨 오차 1.17 rad) |
| 자세 유지 | 위 자세 정착 후 명령 없음 | 30 s | 위치 변화 0.02 rad 이하, 지속 effort/상한 비율 |
| 하한에서 복귀 | 어깨 −1.5708 rad 상태(현재 effort로 처진 상태 재현 또는 하한 목표)에서 P1~P3·영 자세로 | 자세당 20 s | 도달 여부, 정착 시간, 최대 속도(URDF 0.5 rad/s 초과 여부), 오버슈트 |
| 명령 취소 후 유지 | 진행 중 action 취소 | 취소 후 10 s | 정지 시간, 이후 위치 변화 |
| 주행 중 이탈 | 영 자세·대표 작업 자세 유지, 0.3 m/s·0.3 rad/s 주행 10 s 후 정지 | 주행 10 s + 정지 후 5 s | 관절별 최대 이탈과 정지 후 잔류 오차. 이전 팔꿈치 0.038 / 0.020 rad와 비교 |

하중 시험은 계산과 실제 부착을 구분한다. 이 절의 2 kg 값은 계산상 하중이다. 흡착·부착 기능이 미구현이므로 2 kg 하중 유지 시험을 완료했다고 표현하지 않는다. 부착 구현 전에 시험용 고정 결합으로 질량을 붙여 시험하면 "고정 질량 시험"으로만 기록하고, 흡착 성능·보유 판정과 구분한다. 하중은 무부하 → 0.5 → 1.0 → 2.0 kg 순서로 늘린다. 각 단계에서 차체 COM 여유를 `check_static_stability.py`로 따로 확인한다.

1차 비교 결과(2026-10-25, 단일 AX_1·primitive·외부 하중 없음, 격리 headless, 실행마다 새로 시작, 운영 모델 미적용). 후보는 실행별 임시 설치본 사본에만 적용했고, 실행 중 `robot_description`의 effort로 시험 모델을 확인했다.

- 목표 추종: 기존값은 P1·P2·P3·handoff 목표에서 3회 모두 어깨가 하한으로 처져 정착하지 못했고(action 중단), P0·L1·L2만 정착했다. 후보는 7개 자세 21회가 모두 정착했다(팔 전체 4.2~4.3 s, 궤적 4 s 포함, 오버슈트 0). 정착 후 30 s 유지는 정착한 시험 모두 통과(위치 변화 0.000 rad)했고, 정착하지 못한 기존값 시험은 유지 시험을 하지 않았다.
- 최대 관절 속도: 후보는 어깨 0.252·팔꿈치 0.254 rad/s(4 s 궤적)였다. 기존값은 어깨가 중력으로 처지는 동안 매회 0.505 rad/s에 머물렀다(URDF 0.50). 손목 0.700 rad/s(URDF 0.70)는 P3 시험 1회의 짧은 순간값이며, 저장 표본 간격 때문에 발생 시점은 확인하지 못했다. URDF velocity를 1% 넘게 초과한 표본은 없었다. 처짐 속도가 URDF 값 부근에서 멈춘 것은 Gazebo가 velocity 제한을 적용할 가능성을 보여 주지만, 이 시험만으로 강제 여부를 확정하지 않는다.
- 하한에서 복귀: 두 설정 모두 실패했다. 어깨가 −1.5708 rad에 정확히 닿으면 후보 effort에서도 움직이지 않았고, −1.55 rad에서는 복귀했다. 원인은 effort가 아니라 DART 6.13.2가 위치 한계를 넘은 관절에 서보 명령을 적용하지 않는 동작이다(외부 패키지, 상세와 임시 운용 제한은 [인터페이스](../guides/INTERFACES.md)). 해결되지 않았다.
- action 취소 후 유지: 두 설정 모두 취소 후 정지하고 10 s 동안 위치 변화 0.001 rad 이하였다. 기존값의 P2 방향 취소는 어깨가 처지며 2.79 s 뒤에 멈췄고, 후보는 0.08 s였다.
- 주행 중 이탈(0.3 m/s·0.3 rad/s 10 s): 영 자세 최대 이탈 기존값 어깨 0.019·팔꿈치 0.018 rad, 후보 0.0004·0.0006 rad. 후보는 P2 자세도 이탈 0.000 rad였고, 기존값 P2는 정착 실패로 하지 않았다. 차체 roll·pitch는 최대 0.012 rad였다.
- `verify_handoff.py`: 기존값 종료 코드 2(어깨 오차 1.13 rad), 후보 종료 코드 0.
- 반영 후 확인(운영 설치본): 실행 중 `robot_description` effort (10, 100, 65, 25, 5). P0·P1·handoff 목표 추종 정착(최대 4.32 s)·30 s 유지 통과, 오버슈트 0, `verify_handoff.py` 종료 코드 0.
- 자기 충돌은 설정되지 않아(`self_collide` 미설정) 팔과 차체의 겹침을 검출하지 못한다. 빈 월드라 지면 외 외부 물체는 없고, 팔 링크 원점의 지면 위 최소 높이는 0.58 m였다(형상 표면이 아닌 원점 기준). 2 kg 하중, 동적 성능, 안전 게이트·최종 구동 차단은 이 결과에 포함되지 않는다.

## 7. 차체 안정성과 공구 제약

현재 차체 질량 8 kg, 바퀴 각각 0.5 kg도 개발용 값이다. 팔 질량을 위 예산으로 늘릴 때는 차체 질량·관성·접지 조건도 함께 재검토한다. 질량만 임의로 추가해 안정성을 확보했다고 판단하지 않는다. robot_2는 팔이 없으므로 질량·관성·COM을 robot_1과 분리해 산정한다. robot_2의 차체 형상과 분리 범위는 미정이다.

검증 시 팔·공구·상자를 포함한 전체 무게중심과 실제 바퀴 접촉점의 지지 다각형을 구한다. 정적 자세에서는 무게중심 지면 투영점이 다각형 안에 있어야 하며, 내부 경계 여유 50 mm를 초기 목표로 둔다. 가감속에서는 접촉력·전도 모멘트와 바퀴 들림을 추가 확인한다. 주행 시에는 팔을 차체 가까이 접어 운반 자세로 고정한다.

흡착 공구는 상자 윗면에 충분히 위치하는지와 흡착력·전단력·박리 모멘트 한계가 필요하다. 보유 판정은 지정 물체의 실제 부착 상태이며 압력 기반 상태와 구분한다. 고정 관절로 상자를 붙이는 기능만으로 흡착 성능을 통과 처리하지 않는다. 넓은 집게는 마찰·파지력·상자 무게중심과 손가락의 충돌을 검사한다.
