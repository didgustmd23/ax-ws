## Q0-1. "완전 무인"의 정의

이번 프로젝트의 가장 큰 목표는 완전 무인 구현이다. 현재 DESIGN.md는 자동 복구 절차가 없는 실패를
BLOCKED_MANUAL로 두고 사람 확인을 기다리므로, 이 목표와 맞추려면 "무인"의 뜻부터 정해야 한다.

### 자동 복구 절차란

실패 유형마다 미리 정하고 시험으로 검증한, 사람 없이 실행하는 대응 순서다(DESIGN 6절).
원인 분류·최신 상태 확인·검증된 절차·남은 예산이 모두 있어야 자동 복구한다.

| 이미 정의된 자동 복구 | 절차 |
|---|---|
| 물체 검출 일시 실패 | 정지 재관측, 필요 시 Action 종료 → D가 관측 위치로 이동 → 새 Action |
| 들기 전 집기 실패 | 철수 → 재관측 → 다른 검증 후보 |
| 경로 일시 차단 | 제한 대기 → 재계획 → 허용 우회 |
| 정차 오차 | 인계 잠금 전 보정, 잠금 후에는 인계 중단·잠금 해제 절차 |
| 실행 응답 유실 | execution_id로 실제 상태 조회, 재전송 안 함 |
| LLM 지연·형식 오류 | 제안 폐기, 규칙 기본값 |
| 비핵심 노드 종료 | 감독기 재시작 → 상태 재확인 |

센서 만료·위치 상실·통로 모순은 원인이 회복되면 재개한다. 아래 다섯 가지는 현재 자동 복구 방법이 없다.

### 자동 복구가 없는 실패의 해결안(제안)

공통 4단계: **예방 → 국소 복구 → 작업 단위 자동 종료 → 시스템 단위 자동 종료·재기동.** 어느 단계도 사람을 기다리지 않는다.

| 실패 | 예방 | 국소 복구 | 복구 불가 시 |
|---|---|---|---|
| 보유 불명확·낙하 | 흡착 접근 조건 확인 후 부착, 운송 중 적재 감시 | 정지·흡착 유지 → 부착 신호·재관측·적재 판정으로 확정. 집을 수 있는 곳이면 새 집기 시도 | LOST 확정, 작업 FAILED, 물체 "회수 불가" 등록, 낙하 위치를 장애물로 반영, 다음 작업 |
| 관절 한계 고착(DART) | `arm_command_guard` 범위 검사를 계획 단계·최종 게이트에 적용해 발생 0 목표 | 고착 관절만 한계 안쪽으로 재설정(Gazebo 플러그인 필요, 미검증) | 작업 FAILED → 시뮬레이션 자동 리셋·다음 작업 |
| 토크 부족 처짐 | `check_joint_torques.py`로 2 kg 포함 자세별 토크 검사, 초과 자세를 C 후보에서 제외 | 미리 검증한 모멘트 감소 궤적 또는 지지면 내려놓기만 허용, 흡착 해제 금지 | 자세 유지·작업 FAILED, robot_1 사용 불가 → 시스템 SAFE_STOP → 자동 리셋 |
| 제어기·안전 계층 장애 | 독립 watchdog으로 이중화 | 하지 않음(제어·안전 노드는 자동 재시작 제외) | 별도 경로로 정지 → SAFE_STOP → 시험 하네스가 전체 재기동 |
| 원인 불명 상태 변화 | 실패 분류 규칙 확대 | 영향 범위 정지 → 각 소유자 상태 재수신 → 원장 대조, 일치하면 재개 | 작업 FAILED, 물체 "상태 불명" 격리, 로봇 복귀·그룹 상태 재초기화, 다음 작업 |

리셋·재기동은 **사람이 아니라 프로그램**(감독기·서비스 관리자·시험 하네스, 기존 `tools/sim/ax_sim.py` 확장)이 한다.
재기동 상한을 넘어도 풀리지 않을 때만 사람이 원인을 고친다. 그때도 시스템은 안전 정지·기록 상태로 남는다.

### 선택지

| 선택지 | 정의 | 장점 | 단점 |
|---|---|---|---|
| A. 검증 범위 무인(현재 초안) | 자동 복구 불가 실패는 사람 확인까지 정지 | 범위가 작고 안전 판단 단순 | "완전 무인" 목표와 불일치 |
| **B. 운영 무인** | 운영 중 사람 개입 0회. 개별 작업은 실패할 수 있고, 시스템이 자동 종료·격리 후 다음 작업 진행. 사람 확인은 사후 검토 | 목표와 일치, 현실적으로 달성 가능 | 위 해결안 구현·검증 작업 증가 |
| C. 전 작업 성공 | 모든 작업이 사람 없이 성공 | 가장 강한 주장 | 낙하·고착·토크 부족을 모두 자동 회복해야 하며 현재 모델로 보장 불가 |

- B 선택 시 바뀌는 것: BLOCKED_MANUAL은 "작업 자동 종료 + 사후 검토 기록"으로 바뀜(DESIGN 3.3·7절), SAFE_STOP을 정상 종료 상태로 정의, Q6 권고 변경.
- 유지할 원칙: 불확실하면 정지, 흡착 자동 해제 금지, 통로 점유 임의 해제 금지. 무인을 이유로 풀지 않는다.
- 무인 지표: 사람 개입 횟수(목표 0), 작업 성공률, 작업 자동 종료 횟수, 시뮬레이션 리셋·재기동 횟수.
- 시뮬레이션 리셋은 실물에서는 사람의 작업에 해당하므로 결과에서 따로 집계하며, 실물 무인의 근거로 쓰지 않는다.

함께 정할 세부:

- ☐ 프로그램이 하는 시뮬레이션 리셋·전체 재기동을 무인 복구로 인정한다(횟수 별도 보고).
- ☐ robot_1 사용 불가 시 SAFE_STOP 후 자동 재기동을 무인으로 본다.
- ☐ 토크·관절 한계 자세를 C 후보 단계에서 배제하는 예방을 최우선으로 둔다.
- 결정: ☐ A ☐ B ☐ C / 근거: ____

## Q0-2. LLM의 역할 수준

현재 초안에서 결정은 규칙(D와 A·B 안전 계층)이 하고 LLM은 정해진 판단 지점에서 제안만 한다.
즉 LLM은 보조다. D는 규칙 기반 상태 머신이며 Nav2(경로 탐색)·ETA XGBoost(참고 입력)를 쓰지만
진행 여부는 규칙이 결정한다. LLM 비중을 키울 수 있으나 각각 대가가 있다.

| 선택지 | LLM 역할 | 장점 | 대가 |
|---|---|---|---|
| A. 판단 지점 제안(현재안) | 요청 해석, 작업·통로 순서, 집기 후보 선호, 복구안 선택 제안 | 안전·무인 유지가 쉬움, LLM 없이 시험 가능 | LLM 효과가 작게 보일 수 있음 |
| B. 계획 생성 + 규칙 검증 | 작업 전체 계획(단계 순서·대기·우회 전략)을 LLM이 생성, D가 불변조건 검사 후 실행 | LLM이 실질적 계획자. 안전은 규칙이 보장 | 계획 검증기 설계 증가, 검증 실패 시 규칙 계획 대체 필요 |
| C. 미분류 상황 담당 | 규칙에 없는 실패·교착의 진단과 해소안 | 무인 운영의 빈틈에 LLM 강점 사용 | 검증 기준이 가장 약한 영역, 허용 행동을 좁게 제한해야 함 |
| D. LLM 중앙관제 | LLM이 배정·교착 해소를 직접 결정 | "LLM이 관제" 그림이 명확 | LLM 장애 시 운영 정지(Q0-1과 충돌), 재현성 없음, 안전 검증 어려움 |

- 선택 기준: 보여 줄 핵심이 "안전한 무인 운반 시스템"이면 A, "LLM이 협업 로봇을 운영"이면 B.
- 어느 선택이든 LLM이 없을 때의 규칙 경로는 유지해야 Q0-1의 무인 목표가 성립한다.
- B·C 선택 시 바뀌는 것: DESIGN 3.1 판단 지점, 계획 검증기 작업(D4 확장), E-14 평가 방식.
- 함께 정할 것: 발표·보고에서 중앙 Agent와 D의 역할을 어떻게 표현할지.
- 결정: ☐ A ☐ B ☐ C ☐ D ☐ 조합(____) / 근거: ____

## Q1. 발신자 인증은 어디서 구현하는가

인증이 없으면 robot Agent가 중앙 Agent를 사칭할 수 있고, Agent별 권한·격리가 성립하지 않는다.
본문은 인증 검증 전 ASSISTED를 금지한다.

| 선택지 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 기반 설정만 | SROS2로 노드 인증서·Topic별 발행 권한 강제 | 통신 계층에서 사칭 차단 | 설정 부담, 대상 범위 검사는 못함 |
| B. D4만 | 제안의 서명·토큰을 D4가 검증 | 구현 위치가 한 곳 | 통신 계층 위조에 취약, 직접 구현 부담 |
| **C. 기반 설정 + D4** | 통신 계층은 SROS2, D4는 인증된 발신 주체와 sender_agent_id·대상 범위 일치 검사 | 두 단계 방어, 역할 분명 | 두 곳 모두 구현 필요 |

- 공통: E3는 자기 자격 증명으로 연결만 하고 검증하지 않는다.
- 개발 단계는 Agent별 Topic 분리와 모의 인증을 쓰고, 실제 인증 검증으로 보고하지 않는다.
- 함께 정할 것: 기반 설정 담당(A의 기반 운영 또는 별도).
- 결정: ☐ A ☐ B ☐ C / 기반 설정 담당: ____

## Q2. 운영 모드는 누가 소유·전환하는가

모드는 OFF(규칙만) · ADVISORY(기록만) · ASSISTED(검증 제안 반영)다. Agent별 수신 상태
(ACTIVE·QUARANTINED·RECOVERY_SHADOW)는 D가 소유하지만, 모드 소유자는 정해지지 않았다.

| 질문 | 선택지 | 권고 |
|---|---|---|
| 모드 상태 소유 | D 원장 / 별도 관리 도구 | D 원장. 인증 미완료 시 ASSISTED 전환 거절(E-26) |
| 올리는 전환(OFF→ADVISORY→ASSISTED) | 사람만 / 시작 설정 고정 / 자동 허용 | 시작 설정(시험 하네스)으로 고정하고 운영 중 상향 없음. Q0-1이 B·C면 운영 중 사람 명령에 의존하지 않음 |
| 내리는 전환(장애 시) | 사람만 / 자동 허용 | 자동 허용 |
| 전환 시 격리·수신 세대·예산 | 유지 / 초기화 | 유지. 재시작으로 격리를 풀지 않는 원칙과 동일 |

- 위험: 전환으로 격리가 풀리면 격리된 Agent가 우회 복귀한다.
