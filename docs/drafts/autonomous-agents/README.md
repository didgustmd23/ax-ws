# 자율 협업 설계 — 팀 논의용 요약

> 채택 전 임시안의 요약이다. 구현·시험 완료를 뜻하지 않는다.
> 세부 계약과 미확정 사항의 기준은 [임시 설계 본문](DESIGN.md)이다.

## 목표와 책임

robot_1이 집기·적재·하역하고 robot_2가 운송한다. A는 로컬 실행·최종 구동,
B는 관측·위험 판단, C는 조작 전략·결과, D는 주행·그룹 운영을 맡는다.
기능 E의 중앙·로봇별 LLM Agent는 정해진 판단 지점에서 제안한다.
A~E는 기능 구분이며 네 사람의 일대일 담당 배정이 아니다.

정상 단계는 A·D가 진행한다. 후보 의견이 없거나 늦어도 C는 기본 전략을 사용한다.
검증된 실패는 규칙으로 복구하고, 자동 처리 불가능한 경우는 명시적인 사람 확인 대상으로 남긴다.

## 기존 설계 대비 채택 판단 대상

전체 변경 목록과 기존 문서의 수정 위치는 [본문 2절](DESIGN.md#2-기존-설계와의-관계)을 기준으로 한다.

- 주행 호출: A의 주행 Action 클라이언트를 없애고 D가 Nav2를 직접 조정한다. A의 역할별 Action은 잠금·조작 등 로컬 실행으로 한정한다.
- Agent 구성: 기존 D 상위의 단일 중앙 Agent를 기능 E로 분리하고 중앙·robot_1·robot_2의 Agent 3개로 둔다.
- 운영 목표: 정상 작업과 검증된 복구를 사용자 상시 개입 없이 수행하고, 상태가 불명확하면 보류한다.
- AI 장애 대응: 기존 "규칙 기반 복귀"를 "검증된 규칙 절차가 있으면 계속, 없으면 보류"로 바꾼다.
- 일정: 기존 4인·16주 계획을 확장 범위의 확정 일정으로 쓰지 않고 재산정한다. 기존 YOLO·XGBoost·Isolation Forest 범위는 유지한다.

## 기능별 역할 분담

세부 기준: [본문 3절](DESIGN.md#3-기능-ae와-상태-소유권).
아래는 기능의 책임 구분이며, 네 사람은 각 영역의 세부 기능을 나누어 맡는다.

[세부 작업·산출물·인터페이스·의존성·난이도](WORK_BREAKDOWN.md)에서 A~E를 각각
4개, 총 20개 작업으로 나누었다. 현재 진행률과 개인별 배정은 반영하지 않으며,
큰 작업은 내부 산출물 단위로 추가 분할할 수 있게 표시했다.

| 기능 | 주요 개발 업무 | 최종 책임·상태 | 협업 경계 |
|---|---|---|---|
| **A — 모델·제어·실행** | 로봇 모델·Gazebo, 기본 제어, 로컬 Task Executor, 관절 보호·최종 구동 차단, 제어 이상 탐지, 적재 확인, 프로세스 감독기·서비스 관리자 구성 | 로컬 조작 단계·결과, 실제 구동·정지 상태, 원시 부착·해제 신호, robot_2 적재 확인 | D가 승인한 로컬 작업 실행. C에 조작 Action 호출. 주행 명령에도 최종 구동 조건 강제 |
| **B — 위치·환경·안전 판단** | 센서 처리·보정, 위치 추정·TF, 환경 인지 YOLO·위치 이상 탐지, 장애물·위험 판단, 통로 진입·완전 이탈 관측 | 위치·관측 신뢰성, 위험 상태, 통로 관측 결과 | 위험을 A·D에 전달. 실제 정지는 A, 통로 허가·해제는 D가 수행 |
| **C — 인식·조작** | 물체 인식(YOLO)·3D 자세, 집기 후보 생성·성공 확률(XGBoost)·최종 선택, 집기·배치 전략, 조작 결과·실패 분류 | 공구 보유·해제 판정 발행, 조작 후보·결과, 시도별 사용 보고 | A의 조작 Action 요청 처리. D가 위임한 예산 안에서 재시도. 차체 이동 필요 시 A를 통해 D에 보고 |
| **D — 주행·운영** | Nav2·Fleet, 작업 배정·인계 순서, 통로 허가, ETA(XGBoost), 제안 검증, 보류·복구·예산·실행 원장 | 전역 작업·주행 단계, 배정 세대, 그룹 물체 상태, 통로 점유, Agent 격리·수신 상태 | 주행은 직접 조정하고 로컬 작업은 A에 요청. A·B·C의 실제 상태를 근거로 승인·종료 판단 |
| **E — LLM 에이전트** | 중앙·robot_1·robot_2 Agent, 문맥·도구 관리, 작업 순서·후보 선호·복구안 제안, 출력 품질 평가 | Agent의 제안·추론 처리 상태 | 인증된 경로로 D에 제안. A~D의 실제 상태·집기 성공·보류 해제를 직접 확정하지 않음 |

E 내부의 역할도 구분한다.

| Agent | 제안 범위 |
|---|---|
| 중앙 Agent | 운반 요청 해석, 그룹 작업 순서·우선순위·복구안 |
| robot_1 Agent | 자기 조작 작업의 후보 선호, 재관측·재접근·복구안 |
| robot_2 Agent | 자기 운송 작업의 이동·대기·경로 복구안 |

공통 인터페이스는 생산자·소비자가 함께 승인한다(기존 설계 11절). Topic·Service·Action은 기능에 맞게
선택하며, 사람별 배정과 상세 일정은 이 책임표를 바탕으로 별도 확정한다.

## 상세 정책의 기준

판정 조건은 중복 요약하지 않고 다음 본문을 기준으로 검토한다.

- [요청 우선순위·이동 영향 범위](DESIGN.md#32-요청-우선순위와-영향-범위): 이동 허용 주체 D와 운송 중 보류 처리.
- [보류 수명주기](DESIGN.md#33-보류-수명주기): 정지·유효 배정·인계 잠금을 포함한 해제 조건과 실패 종료.
- [Agent 격리·shadow 검사](DESIGN.md#34-agent-접수-예산과-격리): D4가 하네스와 해제 판정을 소유하고 E4는 품질 분석을 지원.
- [실행 권한의 시간 조건](DESIGN.md#54-d-유효성-확인과-c-실행-lease): 요청 시각 기준 기한·Topic 계약.
- [운영 모드·구현 순서](DESIGN.md#10-단계와-미확정-항목): 인증 후 ADVISORY·ASSISTED 단계.

## 팀에서 확인할 범위

- A~E의 권한·호출 경로, 운송 중 보류 정책, 자동 복구와 사람 확인 예외를 채택할지 검토한다.
- 본문에서 아직 정하지 않은 다음 질문을 논의한다. 선택지·권고안·결정 기록은 [팀 결정 항목](DECISIONS.md)에 정리했다.
  - 운영 모드(OFF·ADVISORY·ASSISTED)를 누가 소유·전환하며, 전환 시 Agent 격리·수신 상태를 유지하는가?
  - robot Agent의 이동·정차·대기 제안에 어떤 action 값을 두고, 목표를 등록된 지점 ID로만 받는가?
  - BLOCKED_MANUAL 이후 사람 조치를 거친 후속 작업은 누가 승인하고 복구 예산을 다시 발급하는가?
  - 통로 안에서 운송 중 보류를 받으면 통로 밖 대기 지점까지 이동하는가, 점유를 유지한 채 정지하는가?
  - LLM 형식 오류·지연을 발신자 위반으로 집계해 격리 판단에 넣는가?
  - 발신자 인증을 D4·E3·기반 설정 중 어디서 구현하는가?
  - 기존 A 일정의 보유 판정·G5 관문을 어떻게 고치고, B·C·D 일정 문서를 새로 둘 것인가?
  - `docs/drafts/` 초안을 채택 전까지 git에 보관할 것인가?
- E-24-R은 LLM 없이 D 규칙·관측을 시험한다. E-24-A는 인증 후 실제 Agent 제안의 경로를 시험한다.
- 임계값·횟수, ID 인코딩, 원장 형식, 시계 API, 하네스·알림 구성은 구현·시험에서 구체화한다.
- 개인별 분담·일정은 별도로 산정한다. 채택한 내용은 기존 DETAILED_DESIGN.md에 흡수하고 이 폴더를 별도 운영 기준으로 유지하지 않는다.
