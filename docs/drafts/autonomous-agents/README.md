# 자율 협업 설계 — 팀 논의용 요약

> 채택 전 임시안의 요약이다. 구현·시험 완료를 뜻하지 않는다.
> 세부 계약과 미확정 사항의 기준은 [임시 설계 본문](DESIGN.md)이다.

## 목표와 책임

robot_1이 집기·적재·하역하고 robot_2가 운송한다. A는 로컬 실행·최종 구동,
B는 관측·위험 판단, C는 조작 전략·결과, D는 주행·그룹 운영을 맡는다.
기능 E의 중앙·로봇별 LLM Agent는 정해진 판단 지점에서 제안한다.
A~E는 기능 구분이며 네 사람의 일대일 담당 배정이 아니다.

정상 단계는 A·D가 진행한다. 후보 의견이 없거나 늦어도 C는 기본 전략을 사용한다.
검증된 실패는 규칙으로 복구하고, 자동 처리 불가능한 경우는 명시적인 사람 확인 대상으로 남긴다.

## 기능별 역할 분담

세부 기준: [본문 3절](DESIGN.md#3-기능-ae와-상태-소유권).
아래는 기능의 책임 구분이며, 네 사람은 각 영역의 세부 기능을 나누어 맡는다.

[세부 작업·산출물·인터페이스·의존성·난이도](WORK_BREAKDOWN.md)에서 A~E를 각각
4개, 총 20개 작업으로 나누었다. 현재 진행률과 개인별 배정은 반영하지 않으며,
큰 작업은 내부 산출물 단위로 추가 분할할 수 있게 표시했다.

| 기능 | 주요 개발 업무 | 최종 책임·상태 | 협업 경계 |
|---|---|---|---|
| **A — 모델·제어·실행** | 로봇 모델·Gazebo, 기본 제어, 로컬 Task Executor, 관절 보호·최종 구동 차단, 적재 확인, 프로세스 감독기·서비스 관리자 구성 | 로컬 조작 단계·결과, 실제 구동·정지 상태, robot_2 적재 확인 | D가 승인한 로컬 작업 실행. C에 조작 Action 호출. 주행 명령에도 최종 구동 조건 강제 |
| **B — 위치·환경·안전 판단** | 센서 처리·보정, 위치 추정·TF, 장애물·위험 판단, 통로 진입·완전 이탈 관측 | 위치·관측 신뢰성, 위험 상태, 통로 관측 결과 | 위험을 A·D에 전달. 실제 정지는 A, 통로 허가·해제는 D가 수행 |
| **C — 인식·조작** | 물체 인식·3D 자세, 집기 후보 생성·최종 선택, 집기·배치 전략, 조작 결과·실패 분류 | 공구 보유·해제 관측, 조작 후보·결과, 시도별 사용 보고 | A의 조작 Action 요청 처리. D가 위임한 예산 안에서 재시도. 차체 이동 필요 시 A를 통해 D에 보고 |
| **D — 주행·운영** | Nav2·Fleet, 작업 배정·인계 순서, 통로 허가, ETA, 제안 검증, 보류·복구·예산·실행 원장 | 전역 작업·주행 단계, 배정 세대, 그룹 물체 상태, 통로 점유, Agent 격리·수신 상태 | 주행은 직접 조정하고 로컬 작업은 A에 요청. A·B·C의 실제 상태를 근거로 승인·종료 판단 |
| **E — LLM 에이전트** | 중앙·robot_1·robot_2 Agent, 문맥·도구 관리, 작업 순서·후보 선호·복구안 제안, 출력 품질 평가 | Agent의 제안·추론 처리 상태 | 인증된 경로로 D에 제안. A~D의 실제 상태·집기 성공·보류 해제를 직접 확정하지 않음 |

E 내부의 역할도 구분한다.

| Agent | 제안 범위 |
|---|---|
| 중앙 Agent | 운반 요청 해석, 그룹 작업 순서·우선순위·복구안 |
| robot_1 Agent | 자기 조작 작업의 후보 선호, 재관측·재접근·복구안 |
| robot_2 Agent | 자기 운송 작업의 이동·대기·경로 복구안 |

공통 인터페이스는 생산자·소비자가 함께 검토한다. Topic·Service·Action은 기능에 맞게
선택하며, 사람별 배정과 상세 일정은 이 책임표를 바탕으로 별도 확정한다.

## 보류 상태와 종료

세부 기준: [본문 3.3절](DESIGN.md#33-보류-수명주기).

| 상태 | 처리 |
|---|---|
| 접수 → HOLD_PENDING | 근거·권한·영향 범위를 확인해 다음 단계 시작 차단 |
| HOLD_PENDING → HELD | 진행 중 동작의 검증된 안전 경계와 실제 정지·지지 상태 확인 |
| HELD ↔ RECHECK | 지정 책임자가 원인별 규칙으로 재판정·유한 복구. 해당 원인 아래 허용된 절차만 수행 |
| RELEASED | 사유 해소·이전 동작 종료·물체 상태·양쪽 인계 잠금·다음 단계 조건 확인 후 해당 보류만 종료 |
| BLOCKED_MANUAL | 자동 복구 종료. 그룹 결과 FAILED, 상위 사유 HUMAN_REVIEW_REQUIRED. 통신 복구 소진의 세부 사유는 COMMUNICATION_LOST |

Agent 보류로 팔 동작을 임의 취소하지 않는다. robot_2 운송 중에는 D가 이동 안전성을
확인한 가장 가까운 안전 대기 지점에서 정지시키며, 이동을 검증할 수 없으면 제어 정지한다.
실제 위험에는 본문 3.2절의 안전 정지 우선순위를 적용한다.

보류는 영향 범위에 적용한다. 영향 밖 로봇은 공유 인계·물체·통로 의존과 안전 조건을
확인한 뒤 대기 이동이 가능하다. 통로 해제는 보류 종료와 별개로 B의 완전 이탈 관측에 따른다.

## 실행 권한의 시간 조건

세부 기준: [본문 5.4절](DESIGN.md#54-d-유효성-확인과-c-실행-lease).
초기 범위는 동일 호스트 시뮬레이션이며 감독 시계는 CLOCK_BOOTTIME이다.

| 항목 | 조건 |
|---|---|
| D 유효성 | A의 요청 시각 `tA`와 기간 `H`로 기한 `tA + H` 결정 |
| C lease | C의 요청 시각 `tC`와 기간 `L`로 기한 `tC + L` 결정 |
| 상위 권한 제한 | A 응답 시 `0 < L <= min(lease 상한, tA + H - A 현재 시각)` |
| 최초 실행 | Goal만으로 물리 실행 불가. 첫 시도 전 C→A 요청·응답 필수 |
| 단절·철회 | A의 철회 Topic·Action cancel 또는 lease 만료로 새 시도 차단 |

늦은 응답의 수신 시각으로 기한을 늘리지 않는다. WSL2 절전·시계 신뢰성은 별도 시험 대상이다.

## 운영 모드와 Agent 검증

세부 기준: [본문 10절](DESIGN.md#10-단계와-미확정-항목), [격리 정책](DESIGN.md#34-agent-접수-예산과-격리).

| 모드·수신 상태 | 운영 반영 |
|---|---|
| OFF | 구조화 목표 직접 등록, 규칙 기반 실행 |
| ADVISORY + ACTIVE | 구조화 목표 직접 등록. Agent 제안은 평가·기록만 수행 |
| ASSISTED + ACTIVE | 인증·권한 검증 후 지정 판단 지점에만 반영. C 후보 의견도 이 조건에서만 Goal에 포함 |
| QUARANTINED | 해당 발신 제안 차단. 기존 작업·보류는 독립 규칙으로 관리 |
| RECOVERY_SHADOW | 시스템 모드는 유지하고 해당 Agent 출력만 격리 평가. 실행 효과 없음 |

격리 해제 검사는 두 가지다.

- **D 검증기 검사:** D 계약 시험 하네스가 잘못된 제안 3종을 검증기 사본에 주입한다. 거절 동작을 평가한다.
- **Agent 출력 검사:** shadow 평가 하네스가 snapshot을 제공하고 Agent가 직접 제안을 만든다. 개발용 초깃값은 연속 10건 유효 출력이며, D가 거절한 잘못된 출력은 Agent 검사 실패다.

작업별 보류 예산과 발신자 위반 제한은 별도다. 그룹 예산 소진만으로 특정 Agent를
격리하지 않는다. shadow 통과는 새 수신 세대를 열지만 기존 작업 예산을 초기화하지 않는다.

## 팀에서 확인할 범위

- A~E의 권한·호출 경로, 운송 중 보류 정책, 자동 복구와 사람 확인 예외를 채택할지 검토한다.
- E-24-R은 LLM 없이 D 규칙·관측을 시험한다. E-24-A는 인증 후 실제 Agent 제안의 경로를 시험한다.
- 임계값·횟수, ID 인코딩, 원장 형식, 시계 API, 하네스·알림 구성은 구현·시험에서 구체화한다.
- 개인별 분담·일정은 별도로 산정한다. 채택한 내용은 기존 DETAILED_DESIGN.md에 흡수하고 이 폴더를 별도 운영 기준으로 유지하지 않는다.
