바퀴 회전 병진 원인과 S005 바퀴 미끄럼 설정 후보의 검증 근거를 여러 업무가 같은 자료로 참고하도록 모았다.

|---|---|---|
| A1 | 마찰 설정·주행 자세·적재 지지 구조 판단 | §0.2, §3, §4.1, §5, §9 |
| A2 | 구동·정지·odom 오차 검증 | §2~§6, `measurements.csv` |
| A4 | 주행 허용 조건·외곽·정지 판단 참고 | §4.1, §6.3, §8 |
| B2 | 지도·위치 추정 영향과 재검증 | §7, §11 |

### 0.2 A1 판단 요청 (요약)
1. **S005를 두 로봇의 개발용 설정으로 반영할지.** 매크로가 공통이라 반영하면 robot_1·robot_2가 함께 바뀐다. robot_1은 옆으로 치우친 하중 진단에서 S005로도 병진이 남는다(최대 0.283 m, §6.2).
2. **robot_1 주행 자세와 외곽을 어떻게 정의할지.** 현재 시험 자세 neutral은 확정 주행 자세가 아니며, 팔이 차체·바퀴 외곽보다 왼쪽으로 0.225 m 돌출한다(§4.1).
3. **robot_2 적재 지지 구조와 적재 주행 검증을 어떻게 진행할지.** 검증된 지지·고정 방식이 없어 적재 상태 주행은 미검증이다(§6.1).

세부 요청(생성기 COM 의도, 출발 위치 기둥 등)은 §9에 있다.
**반영 뒤 순서:** ① 구동 재검증(회전·직진·곡선·정지, 두 로봇) → ② AWS 지도 재생성·정확도 평가(B2). 이 순서와 결과는 A4 안전 기능 구현·G1 완료와 별개다.

### 0.4 읽는 법과 파일
- 이 자료는 바퀴 마찰 설정의 **운영 모델 반영 여부를 A1이 판단하고, 관련 업무가 같은 근거를 참고하기 위한 검증 자료**다. 후보를 채택하거나 운영 모델·생성 파일을 수정하지 않았고, 질량·COM·effort·바퀴 보정값도 바꾸지 않았다.
- 결과는 설치된 버전(gz-sim 8.15.0, gz-physics 7.8.0 dartsim, DART 6.13.2)과 아래 시험 조건에서 확인한 거동이다. 물리 엔진 전반의 결함으로 단정하지 않는다. A4 안전 기능이나 G1 충족 근거가 아니다.
- **COM 편심 자체를 결함으로 판단하지 않는다.** 접촉·하중·COM 이동 실험은 현재 설정의 거동을 설명하는 근거다.
- 표의 값은 반올림했다. **반올림 전 값은 `measurements.csv`에 그대로** 있다. 단, robot_2 원인 조사 회전 6회(§3.1)는 원본 JSON부터 소수 셋째 자리다.

## 1. 문제

제자리 회전(그리고 곡선 주행)에서 **차체가 실제로는 평행 이동하는데 바퀴 odom은 이를 반영하지 못한다.**
robot_2·robot_1 모두 재현된다. 회전각은 대부분 맞고 위치만 어긋나지만, robot_1에서 팔을 옆으로 뻗고 2 kg 고정 치구를 단 진단 조건에서는 odom 회전각까지 크게 틀린다(§4.3).
B2 지도 작성에서는 이 어긋남 뒤에 SLAM 방향 오차(약 0.3 rad)가 생기고 유지됐다.

## 3. robot_2 관측과 원인 근거

### 3.1 관측 (기본 설정, 평면 바닥 `ax_test.world`, 무부하)
좌·우 각 3회, 0.3 rad/s 10 s 명령(약 3.0 rad). 반복별 값: `group=cause_rotation`.

| 항목 | 6회 결과 |
|---|---|
| 실제 / odom 회전각 | 3.001~3.007 / 3.000~3.006 rad (차이 ≤ 0.001 rad) |
| 실제 차체 병진 / odom 병진 | **0.666 m** / 0.000 m (6회 모두) |
| 회전 중심(시작 차체 기준) | **(+0.334, −0.002) m**, 반지름 0.334 m. 좌·우 같음 = 앞바퀴 축 가운데(앞바퀴 x +0.3337, y +0.4165/−0.4202) |
| 기준점 확인 | Gazebo `dynamic_pose`의 base_link 링크 자세가 모델 기준 (0,0,0) → 모델 원점 = base_link |
| 네 바퀴 | 회전 방향 정상, 속도 모두 0.948 rad/s, 바퀴 중심 높이 모두 0.1499 m |

### 3.2 질량·무게중심 (생성기 결과 그대로)
- `ax_2_physical_properties`의 링크 질량(차체 12 kg, 선반 5 kg, 상단 하우징 0.4 kg, 바퀴 0.4 kg×4 등)을 URDF 관절 변환으로 합산하면 전체 COM은 base_link 기준 **x = +0.0257 m**로, 바퀴 중간(x = −0.0023 m)보다 0.028 m 앞이다.
- 이 COM으로 예측한 정적 앞바퀴 하중 비율 0.5416이 접촉 센서 실측 0.5418과 일치한다.
- 생성기(`tools/generate_physical_properties.py` `generate_ax2()`)는 질량 예산을 메시 근사 상자 부피 비율로 배분하며, 결과는 이 방식과 맞다. 의도한 COM 값이 따로 정해져 있는지는 확인하지 못했다(판단 요청 1).

### 3.3 바퀴별 접촉·하중·마찰력 (조사용 접촉 센서를 단 사본)
`group=cause_contact`. 수직 하중은 바퀴별 합, 마찰력은 접촉점당 평균이다(바퀴당 접촉점 2개, 위치는 바퀴 바로 아래).

| 바퀴 | 정지 수직 하중 | 회전 중 축(옆) 방향 마찰력 | 마찰 한계 0.1×하중/2 | 상태 |
|---|---|---|---|---|
| 앞 좌·우 | 52.9 / 52.5 N | −2.22 / −2.24 N | 2.64 N | 한계 미만 → 미끄러지지 않음 |
| 뒤 좌·우 | 44.8 / 44.4 N | +2.25 / +2.22 N | 2.24 N | 한계 도달 → 미끄러짐 |

### 3.4 원인 분리 사본 시험 (현재 설정의 거동 설명용)
`group=cause_variant`. 한 번에 한 조건만 바꿨다.

| 사본 조건 | 결과 | 해석 |
|---|---|---|
| `fdir1` 제거 | 차체 회전 0 rad(바퀴만 회전, odom 3.0 rad) | 축 방향 마찰 설정이 적용되고 있음 |
| `mu1` 0.1 → 1.0 | 기본과 같음(병진 0.666 m, 중심 앞 축) | 어느 쪽이 미끄러질지는 앞뒤 하중 비율로 정해져 계수 크기와 무관 |

## 9. A1 판단 요청

1. **생성기 COM 의도:** robot_2 COM(바퀴 중간보다 0.028 m 앞), robot_1 COM(0.099 m 앞, 0.054 m 왼쪽)이 의도한 질량 배분인지. COM 편심 자체를 결함으로 보지는 않는다. 바꾼다면 생성기로 재생성한다.
2. **마찰 후보의 물리적 타당성:** 옆방향 미끄럼 순응(`slip1` 0.05 m/s/N)을 운영 모델의 시뮬레이션 가정으로 받아들일 수 있는지. 값의 근거는 이 시험 거동뿐이다.
3. **robot_1 적용 여부:** 매크로가 공통이라 반영하면 robot_1도 바뀐다. robot_1은 옆으로 치우친 하중에서 S005에서도 병진이 남는다(최대 0.283 m). 같은 값을 쓸지, 로봇별 값을 둘지 판단이 필요하다.
4. **robot_1 주행 자세 정의:** neutral을 주행 자세로 쓸지, 차체 안으로 접히는 별도 자세가 필요한지.
5. **출발 위치:** robot_2 출발 위치 (2.5, −1.5) 주변(AWS 월드) x_world 2.78에 LiDAR에 보이는 가는 기둥들이 차체 안쪽(0.31 m)까지 들어온다(A1 launch 배치).
6. **추가 시험 필요 여부:** §10 미검증 조건 중 반영 전에 확인할 것

## 10. 미검증 조건·운영 제한

- 물리 설정(질량·마찰·effort)은 개발용 잠정값이다. 시험 수치는 성능값이 아니다.
- 물리 비교는 **평면 바닥**에서만 했다. 원본 AWS 메시 바닥, 경사·턱은 시험하지 않았다.
- 회전 0.15~0.50 rad/s, 직진 0.3·0.67 m/s, 곡선 0.3 m/s·±0.3 rad/s만 시험했다. 다른 곡률, 급가감속은 시험하지 않았다.
- robot_1: 작업 자세는 `reach_side`(왼쪽) 하나만 진단했다. 오른쪽·앞쪽 뻗음, `reach_max`, 다른 공구는 미시험이다. 하중은 고정 치구 2 kg까지다.
- robot_2: 적재 상태(0.5·1·2 kg) 주행은 지지·고정 방식이 없어 미실행이다. 적재면에 올려놓은 상자 시험은 민감도 진단 자료다.
- `slip1`은 0.05·0.20만 시험했다(robot_2). 다른 값은 미시험이다.
- 실물 타이어·바닥 마찰과의 대응은 근거가 없다.
- B2 결과는 `light_collision` 월드, 앞 LiDAR만, 기존 SLAM 설정 조건이다. 지도 정확도는 판정하지 않았다.
- 같은 앞 LiDAR를 쓰는 참조 지도와 비교했으므로, 센서 오차·가림과 LiDAR 높이(robot_2 앞 LiDAR 바닥 위 약 0.41 m)에서 보이지 않는 장애물(예: 긴 선반은 다리만 보임)은 두 지도가 함께 놓친다.
