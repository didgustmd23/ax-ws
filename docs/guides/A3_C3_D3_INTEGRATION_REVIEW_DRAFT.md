# A3·C3·D3 연결·사유 코드 검토 초안

작성일: 2026-11-14 · 초안 작성: 김성민 담당 작업 기준 · 상태: **관련 담당자 검토 대기**

이 문서는 구현된 사실과 상대 담당자에게 제안하는 행동을 구분한다. 검토자를 대신해 승인하지 않는다.
새 코드 15종의 D-13 등록, 상대 기능 변경, 실제 연결 완료를 선언하는 문서가 아니다.
요약과 기존 근거는 [C3·D3 인계 문서](C3_D3_CONTRACT_HANDOFF.md)를 함께 본다.

## 1. 현재 출발점과 역할

| 연결 | 김성민 쪽 준비 | 상대 쪽 준비·확인 | 현재 경계 |
|---|---|---|---|
| A3 ↔ D4 | 배정 확인 요청·응답 대조, 주기 확인, 만료·오류 무효화 | D4 실제 원장을 기준으로 확인 응답 구현 | 모의 D4 시험만 있음. 실제 배정 응답 연결 미완료 |
| A3 ↔ A4 | CheckCommandLease 운영 판정·중복 검사·원장 | A4 실제 명령 수락·진행 확인·차단 동작 | 실제 팔 실행과 종단 정지 검증 미완료 |
| C2 → C3 → C4 | 내부 Surface/Constraints/Plan API, 후보 게시·만료 정리 | C2 실제 관측, 실제 IK·충돌 검증기, C4 소비 연결 | 입력 Topic을 임의로 만들지 않았음. 단독 노드는 빈 후보 |
| B3·D2·A4 → D3 → D1/D2·A4 | 원장·요청 응답·관측/정지/배정 검증 | 영역과 허가 정책 합의, 실제 요청·허가 소비 | **새 허가 발급 보류**, 기존 원장 보존 |

김성민은 출력의 형식·사유·기한과 시험 입력을 준비한다. 상대 담당자는 실제 입력과 소비 동작을
확인한다. 안전 정지·주행·작업 재배정·집기 전략을 이 문서만으로 김성민 코드에서 대신 실행하지 않는다.

## 2. 공통으로 제안하는 처리 원칙

1. 알 수 없는 사유 코드도 성공으로 해석하지 않고 실행을 보류한다. 상세 대응은 소비자가 결정한다.
2. 같은 요청 ID의 재전송은 기존 결과 재현이다. 원인이 회복된 뒤 새 판정이 필요하면 새 요청 ID를 쓴다.
   동일 물리 명령 ID는 새 요청 ID를 써도 다시 실행하지 않는다. lease 재검사 예외는 계약 5.2절을 따른다.
3. 재시도 횟수·간격·예산은 기존 계약과 작업 예산을 따른다. 무한 자동 재시도를 새로 도입하지 않는다.
4. 상태 목록은 최신 전체 snapshot으로 교체한다. 사라진 C3 후보를 이전 목록에서 되살리지 않는다.
5. 오류가 여러 개면 현재 검사 순서상 첫 사유가 나온다. 모든 사유가 동시에 반환된다고 기대하지 않는다.
6. 문서의 ‘제안 대응’은 아직 상대 노드에 구현됐다는 뜻이 아니다.

## 3. D3 사유 코드 6종

아래 발급 관련 조건은 **정책 활성화를 가정한 개발 구현**의 의미다. 현재 운영 기본값에서는
정책 미합의가 먼저 검사되어 새 요청에 AUTHORITY_INVALID가 나온다. 영역 미승인은 그보다 먼저 검사한다.
과거 요청 재전송은 저장 응답을 반환한다. 원장 장애는 어댑터에서 서비스 판정을 차단한다.

| 코드·시험 ID | 현재 발생 조건·내 출력 | 소비자 대응 제안 | 복구·재시도 제안 | 통과 기준 |
|---|---|---|---|---|
| STOP_NOT_CONFIRMED · D-01 | A4 정지 확인 없음·만료 또는 속도 기준 미충족. 신규 허가 거절 | 진입 보류. 정지 요청·확인은 D1/A4 담당 | 신선한 실제 STOPPED 확인 뒤 새 요청. 배정·관측 조건도 재확인 | 미정지에서는 거절, 정지만 회복돼도 다른 조건이 나쁘면 계속 거절 |
| WAITING_TURN · D-02 | 통로가 FREE지만 FIFO 선순위가 다른 로봇. 허가 거절 | 실패로 즉시 종료하지 말고 작업 예산 안에서 대기 | 대기 유지·취소·새 요청 주기는 D1/D2와 결정 | 후순위가 선순위보다 먼저 허가받지 않음. 대기표 만료가 기존 허가를 삭제하지 않음 |
| GRANT_MISMATCH · D-03 | 해제 ID 누락 또는 owner/grant 불일치 | 원장 상태 확인. 임의 grant 추측이나 강제 해제 금지 | 최신 상태와 실제 소유 관계 확인 후 올바른 요청 | 다른 로봇·옛 grant로 해제 불가, 현재 owner/grant 보존 |
| EXIT_NOT_CONFIRMED · D-04 | 허가 이후의 신선한 완전 OUTSIDE 관측 없음 | 시간초과를 이탈로 간주하지 않고 관측 확인 | 실제 이탈·새 관측 확보 뒤 새 해제 요청 | 허가 전 OUTSIDE·INSIDE·만료 관측으로 해제되지 않음 |
| CORRIDOR_LEDGER_FAILED · D-05 | SQLite 조회·저장 오류. 서비스 거절·상태 무효를 고정 | 진입 보류, 담당자에게 원장 점검 요청 | 원인 복구·원장 검증·재시작 및 새 실제 관측 후 재시험. 자동 복구 승인 기준 별도 결정 | 원장 오류 뒤 다른 요청도 거절, 조용히 정상으로 복귀하지 않음 |
| REGIONS_NOT_APPROVED · D-06 | B3 영역 설정 approved=false | 승인 전 발급 요구를 반복해 우회하지 않음 | 지도·TF·외곽·진입/이탈 검증과 담당 검토 후 승인. D3 정책 합의도 별개로 필요 | 미승인 때 발급 없음. 영역 승인만으로 정책 보류가 풀리지 않음 |

검토자: 김성민(D3) + D1/D2 허가 요청·소비 담당 + 승연님/A4 + 계약 담당자.
GRANT_MISMATCH·EXIT_NOT_CONFIRMED는 해제 경로이며 실제 진입 허가와 구분한다.
다른 로봇의 관측이 불명일 때 해제를 보류하는 CORRIDOR_BLOCKED는 별도 정책 검토 항목이다.

## 4. C3 사유 코드 9종

입력은 내부 API의 Surface/Constraints 자료형을 전제로 한다. 임의의 손상된 Python 객체까지
모두 사유 코드로 변환한다는 의미는 아니다. API 호출 예외와 후보 상태 사유는 구분해 처리한다.
검사 순서는 수치 → 관측 식별/시각 → 제약 → 공구 조건 → 검증기 유무 → 표면 축 → 접촉 크기 → 후보 필터다.

| 코드·시험 ID | 현재 발생 조건·내 출력 | 소비자 대응 제안 | 복구·재시도 제안 | 통과 기준 |
|---|---|---|---|---|
| CANDIDATE_STALE · C-01 | 관측 기준 또는 최초 수신 벽시계 기한 만료, 미래 시각 등. 후보 무효 | 후보 선택·새 동작 수락 금지. 최신 목록으로 교체 | 새 관측의 새 후보를 기다림. 동일 결과 재전송으로 연장 금지 | 만료 후보 미사용, 8개 만료 후 9번째 수용, 옛 버전 재수신 거절 |
| NO_VALID_CANDIDATES · C-02 | 입력 후보 없음 또는 모든 후보가 실제 검증을 통과하지 못함 | 후보 부재만으로 전체 작업 실패를 확정하지 않음 | C4/D2가 재관측·다른 전략·종료를 예산 안에서 결정 | 빈 결과를 임의 좌표로 대체하거나 집기 성공으로 처리하지 않음 |
| INVALID_GEOMETRY · C-03 | 중심 차원 오류 또는 계산 스칼라·중심의 비유한수 | 입력 담당자에게 잘못된 값 전달, 실행 보류 | 유효한 관측·제약 수정 후 재계산 | NaN·Inf·잘못된 중심 차원에서 유효 후보 없음 |
| OBSERVATION_STALE_OR_INVALID · C-04 | 로봇/물체/좌표계 누락, revision·시각 무효, 관측 미래/만료 | 해당 관측으로 실행하지 않음 | C2의 신선한 관측과 올바른 식별 정보 필요 | 이전/미래 관측이 정상 후보로 게시되지 않음 |
| CONSTRAINTS_INVALID · C-05 | 공구 크기·하중·거리·기한의 양수 조건 또는 여유·신뢰도·평탄도 한계 위반 | 설정 문제로 분류, 같은 설정의 반복 재시도 억제 | A1/A2/C4와 검증한 값으로 수정하고 제약 버전 관리 | 잘못된 제약으로 후보 없음. 검증된 수정 제약에서 재계산 가능 |
| TOOL_CONDITIONS_NOT_MET · C-06 | 흡착 부적합, 신뢰도 부족, 질량·평탄도 조건 불충족 | 현 표면·공구 조합으로 실행하지 않음 | 재관측·다른 표면·전략 전환을 C4와 결정 | 질량·신뢰도 등 각 조건을 독립 위반시켜 필터링 확인 |
| VALIDATORS_UNAVAILABLE · C-07 | 도달성 또는 경로 충돌 callback 미제공 | 검증기 연결 전 실행 보류 | 실제 모델·관절 한계·환경에 연결된 검증기 제공 | None 검증기로 후보 없음. 항상 True 모의 함수는 실제 연결 통과로 인정하지 않음 |
| SURFACE_AXES_INVALID · C-08 | 법선·접선이 유한한 비영 3D 벡터가 아니거나 직교하지 않음 | 잘못된 공구 방향으로 실행하지 않음 | C2와 표면 축·좌표계를 수정 | 영벡터·잘못된 차원·비직교 입력에서 후보 없음 |
| CONTACT_SURFACE_TOO_SMALL · C-09 | 접촉 폭·깊이와 가장자리 여유를 표면이 수용하지 못함 | 중심점만 들어간다고 실행하지 않음 | 다른 표면·공구 또는 검증된 전략을 선택 | 접촉 면적 부족 시 후보 없음. 유효한 경계 안 후보만 생성 |

검토자: 김성민(C3) + C2 관측 제공자 + C4 후보/실행 소비자 + 공구·검증기 관련 담당자 + 계약 담당자.
검증기가 제공됐지만 False를 반환하거나 예외를 내면 해당 후보를 제거한다. 모든 후보가 제거되면
NO_VALID_CANDIDATES이며 VALIDATORS_UNAVAILABLE와 구분한다.
게시 전체의 meta 사유와 개별 candidate_set의 meta 사유는 다를 수 있으므로 소비자는 둘을 확인한다.
만료 사유는 한 차례 게시 후 후보 공간이 회수될 수 있다. 이후 전체 목록에서 빠지는 것 역시 무효화다.

## 6. 실제 연결 시험 계획

### 공통 시작 조건

- [ ] 담당자와 합의한 domain을 기록하고 공용 예약·잠금·노드/서비스 충돌 검사를 통과한다.
  현재 kim_ros_test_domain 도우미는 승인된 1~99의 범위를 명시해야 하며 미지정 시 시험을 건너뛴다.
- [ ] 모든 노드의 use_sim_time과 /clock, 로봇 ID·모델·namespace를 맞춘다.
- [ ] 소스 커밋과 로컬 diff, 실제로 빌드한 설치 경로, 지도·영역·모델·설정 해시를 기록한다.
- [ ] 참여 노드가 실제인지 모의인지 적는다. 모의 상대가 하나라도 있으면 실제 전체 연결 완료로 표시하지 않는다.
- [ ] 중단·정지 확인 방법과 시험 운영 책임자를 정한다. 정지·재시작의 물리 영향은 해당 담당자가 확인한다.
- [ ] B3 영역은 실제 검증·승인 전 운영 근거로 쓰지 않는다. D3 시험 활성화는 격리된 시험 사본에서만 한다.

### A3 시험

| ID | 실제 연결 시험 | 통과 기준 |
|---|---|---|
| A-01 | 실제 D4 배정으로 A3 요청·응답 대조 | 원장과 맞는 배정/세대만 유효. 다른 로봇·세션·과거 응답은 무시 |
