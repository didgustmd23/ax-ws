# A3 K0 계약 검토 기록 — 김성민 담당 W0

기록일: 2026-11-08. 대상 작업: 10월 W0의 A3 실행기 골격·모의 서버.
이 문서는 현재 코드와 계약을 대조한 A3 범위의 검토 기록이다.
김성민 본인의 승인이나 다른 생산자·소비자의 공동 승인을 대신하지 않는다.
**승인 상태: 초안.** 공동 승인 전까지 유지한다.
공통 승인 현황은 [K0 계약 7.3절](../design/INTERFACE_CONTRACT.md#73-승인-현황)을 따른다.

## 검토 대상과 결과

| 계약·타입 | 검토 여부 | 확인 결과·후속 사항 |
|---|---|---|
| `ExecuteLocalTask` (계약 5.1절) | W0 모의 구현과 대조 완료 | `CONFIRM_LOAD=5`, Feedback의 `phase`·`progress`, Result의 `status`·`load_state` 사용 확인. 다른 작업·revision 기록·예산·취소는 미구현 |
| `ExecutionRef` (계약 2.5·5.1절) | W0 모의 구현과 대조 완료 | 비어 있지 않은 실행 ID만 검사. D의 ID 파생 규칙·배정 세대·원장·재시작 복구는 미구현 |
| `ResultStatus` | 모의 결과 매핑 검토 완료 | STOWED → SUCCEEDED, EMPTY → FAILED, UNKNOWN → UNCERTAIN. 불명 상태는 성공으로 처리하지 않음. `MOCK_EMPTY`·`MOCK_UNKNOWN`은 시험 전용 오류 코드 |
| `LoadState`·`StateMeta` (계약 2.3·4.3절) | 상수 사용과 상태 발행 범위 대조 완료 | Result는 적재 상태 상수만 사용. 운영 `LoadState` Topic과 관측 근거·시각·유효성은 미구현. 시험 표시용 `String` Topic은 운영 상태 Topic이 아님 |
| `ManipulateObject`·배정 확인·실행 lease·`CheckCommandLease` (계약 4.3·5.2절) | 계약 내용 검토, 구현 검증 미수행 | A3의 권한·lease·세대·명령 수락 기록 책임 확인. W0 모의 서버는 해당 경로를 구현하거나 물리 명령을 발행하지 않음 |

## 이의·확인 요청과 구현 차이

1. **같은 실행 ID 재요청:** 계약 5.1절은 기존 실행·결과에 연결하도록 요구하지만 모의 서버는 메모리의 `seen`에 있는 ID를 거절한다. W0 시험의 제한이며 운영 계약 충족으로 볼 수 없다. 후속 A3 구현에서 영속 원장·재연결·인자 변경 검사가 필요하다.
2. **EMPTY의 결과 의미:** 현재 적재 확인 시험은 EMPTY를 FAILED·ABORTED로 반환한다. 운영 `CONFIRM_LOAD`에서 비어 있음의 정상 확인도 실패로 볼지, 확인 성공과 적재 상태를 분리할지는 D4 등 소비자와 공동 확인이 필요하다. 현재 매핑을 운영 규칙으로 확정하지 않는다.
3. **관측 근거:** `mock_load`는 사용자가 지정한 시험 입력이다. 센서·Gazebo 객체 관측으로 얻은 판정이나 운영 `LoadState` 근거로 사용하지 않는다. LOST 판정은 시험하지 않는다.
4. **운영 계약 미검증:** 취소·timeout·예산·배정 확인·lease 갱신/철회·재시작·영속성은 후속 구현과 계약 시험 대상이다. 공통 Action·메시지 정의 변경은 이번 수정에서 적용하지 않는다.

공동 확인이 필요한 항목은 위에 남겨 두며, 이 기록만으로 이의 없음 또는 승인 완료로 처리하지 않는다.
