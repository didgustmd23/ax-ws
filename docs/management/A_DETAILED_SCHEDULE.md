# AX 담당 A 상세 개발 일정

> 이 문서의 시작 상태는 일정 작성 당시 기준이다. 최신 적용·검증 상태는 [문서 안내](../README.md)와 [업로드 전 점검](../validation/PREUPLOAD_REVIEW.md)을 참고한다.

> 기준: [통합 상세설계](../design/DETAILED_DESIGN.md), [현재 인터페이스](../guides/INTERFACES.md), [현재 점검 결과](../validation/PREUPLOAD_REVIEW.md).
> A 담당자 1명, 주 5일, 총 16주를 기준으로 작성한 실행 계획이다. 착수일이 정해지지 않았으므로 상대 주차를 사용한다.
> 세부 작업·일별 배분·정량 검증안은 일정 구체화를 위한 제안이다. 현재 구현 완료 상태나 확정 사양을 의미하지 않는다.
> 프로젝트·패키지·네임스페이스는 `AX` / `ax`로 통일한다.

## 1. A의 목표와 담당 범위

A는 로봇 모델과 기본 제어를 제공하고, D가 배정한 작업을 로봇별로 실행하며, B의 위험 판단에 따라 최종 구동을 차단한다.

| 구분 | A 담당 내용 | 협업 경계 |
|---|---|---|
| 모델 | Xacro, 링크·관절, 충돌·관성, 센서 장착 프레임 | 센서 사양은 B/C와 협의 |
| 시뮬레이션 | Gazebo 생성, 브리지, 시간·피드백, 두 로봇 실행 | 창고·통로 조건은 B/D와 공동 확정 |
| 기본 제어 | 바퀴·팔·집게의 저수준 연결, 제한 검사, 최종 안전 차단 | Nav2 주행은 D, 집기 계획·성공 판단은 C |
| 작업 실행 | ExecuteTransportTask 서버, 주행·조작 Action 클라이언트, 내부 상태 머신 | 전역 작업 소유·배정은 D |
| 오류·취소 | 하위 동작 취소, 정지 확인, 결과 보고, 재개 조건 검사 | 재배정은 D, 집기 제한 재시도는 C |
| 제어 ML | 제어 로그·오류 주입, Isolation Forest, 진단 출력 | B의 위험 판단과 물리적 제한을 대체하지 않음 |
| 통합 지원 | 공통 계약 테스트, 실행 상태 제공, Agent 평가 지원 | 중앙 Agent 구현·검증은 D 주도 |

주요 산출 패키지: `ax_description`, `ax_simulation`, `ax_control`, `ax_task_executor`, `ax_control_ml`.

공동 산출 패키지: `ax_interfaces`, `ax_bringup`, `ax_integration_tests`. `ax_operations_agent`는 D 주도이며 A는 실행 상태·로그·계약 테스트를 지원한다.

## 2. 시작 시점의 확인된 상태

다음은 기존 문서·검증 기록 기준이며, 이번 일정 작성 과정에서 시뮬레이션을 재실행한 결과는 아니다.

| 항목 | 기록상 상태 | 일정 반영 |
|---|---|---|
| 개발용 모델 | 상자·원통 기반, 링크 14개·관절 13개 | 1~2주 모델·기구 사양 정리 |
| 실제 모델 | 실제 OBJ·관절 실측값 미반영 | 자료 확보와 모델 교체를 별도 관리 |
| 빌드·생성 | 두 패키지 빌드, Gazebo 모델 생성 확인 | 1주 재현 기준선 확보 |
| 팔·집게 | 7개 명령 전달·움직임 확인 | 2주 목표 추종·범위 검사 개선 |
| 위치 정확도 | 일부 관절이 임시 오차 기준 초과 | 원인 분리 후 재검증 |
| 라이다 | `/scan` 전달 확인, 장애물 거리 정확도 미검증 | 3주 환경·센서 검증 |
| 상태·시간 | ROS `/joint_states`, `/clock`, `/odom` 발행기 없음 | 3주 연결·검증 |
| 주행 | ROS `/cmd_vel`, odom·주행 TF 연결 미제공 | 3~4주 기본 주행 인계 |
| 두 대 실행 | 고정 임시 URDF 파일·단일 모델 구성 | 4주 로봇별 생성·네임스페이스 분리 |
| 고수준 실행 | 현재 소스 목록에 Task Executor·제어 ML 패키지 없음 | 5주 이후 신규 구현 |

이미 확인된 기능도 새 구성에서 다시 확인한다. 기존 명령 전달 성공을 목표 추종·집기 성공으로 간주하지 않는다.

## 3. 단계별 목표

| 단계 | 기간 | A 완료 목표 | 선행 조건 |
|---|---|---|---|
| 기반 구성 | 1~4주 | 두 로봇 모델·명령·센서·TF 분리, 안전 제어 경로 확정 | B/C/D 인터페이스 협의 |
| 한 대 실행 | 5~8주 | 작업 실행·정지·취소·복구를 포함한 한 대 운반 | D 주행, C 조작, B 안전 연결 |
| 두 대 통합 | 9~10주 | 독립 실행, 이전 배정 결과 차단, 통로 대기·취소 연계 | D 배정·통로, B 관측 |
| 제어 이상 탐지 | 11~12주 | 데이터·모델·진단 노드·실패 시 복귀 | 명령·실제 상태 로그 |
| Agent 연계 지원 | 13~14주 | 실행 상태 제공, AI 개입 중 안전·취소 검증 | D Agent·검증기 |
| 최종 검증·인계 | 15~16주 | 반복 시험, 결함 수정, 재현 가능한 인계 | 팀 전체 통합 |

## 4. 주차별 상세 일정

각 주는 1~2일 설계·핵심 구현, 3~4일 연결·검증, 5일 통합·결함 수정·기록을 기본으로 한다. 5일차는 신규 기능을 늘리기보다 주차 완료 조건을 충족하는 데 사용한다.

### 1주차 — 기준선과 공통 계약

- 1~2일: 기존 빌드·모델·명령·센서 실행을 재현하고, 확인된 기능과 미구현 항목을 기록한다. 실제 모델 자료, 관절 축·치수·질량·제한값의 확보 여부를 정리한다.
- 3~4일: B/C/D와 로봇 ID, `/ax` 접두사, TF, 시간·단위, Action 필드·종료 상태·오류코드를 정한다. Nav2·조작 명령에서 실제 제어기까지의 안전 차단 위치를 설계한다.
- 5일: 계약 초안과 상태 소유권을 공동 리뷰하고, 변경 담당자·검증 방법을 확정한다.
- 산출물: 기준선 실행 기록, 미확정 사양 목록, `ax_interfaces` 초안, 안전 제어 경로도.
- 완료 기준: A↔B 안전, A↔C 조작, A↔D 작업·주행의 입력·출력·취소 책임이 문서로 연결된다. 필요한 정지 지연·목표 오차의 측정 방법과 허용값 확정 시점을 기록한다.

### 2주차 — 모델과 관절 제어 개선

- 1~2일: 확보된 기구 자료로 축·원점·충돌·질량·관성을 검토한다. 실제 자료가 없으면 개발용 모델임을 표시하고 확인 가능한 설정부터 정리한다.
- 3~4일: 관절별 단독 명령으로 어깨 방향·목표 추종·손가락 상한 문제를 분리 조사한다. 이득·감쇠·하중·충돌 영향을 확인하고 명령 범위·비정상 입력 검사를 구현한다.
- 5일: 여러 목표값에서 위치 오차와 정착 상태를 기록하고 C에 팔·집게 사용 범위를 전달한다.
- 산출물: 수정 Xacro·제어 설정, 관절별 측정표, 명령 입력 계약.
- 완료 기준: 목표 추종을 측정할 수 있고 오류 원인·잔여 문제가 기록된다. 운반에 사용할 관절 범위에서 합의한 허용 오차를 만족해야 실제 집기 통합으로 진행한다.

### 3주차 — 시간·상태·기본 주행 연결

- 1~2일: `/clock`, `use_sim_time`, `/joint_states` 피드백과 이동 관절 TF를 연결한다. 팔 제어를 유지하는 정지 방식과 이동을 차단하는 경로를 구분한다.
- 3~4일: ROS 주행 명령, odometry, `odom → base_link`를 연결한다. 센서 장착 프레임·메시지 timestamp를 확인하고 장애물을 둔 라이다 거리 검증을 수행한다. RGB/Depth 장착·브리지 조건은 B/C와 맞춘다.
- 5일: 전진·회전·정지 및 명령 중단 동작을 확인하고 D/B에 인계한다.
- 산출물: 브리지 설정, 상태·시간 연결, 기본 주행 측정 기록, 센서 연결표.
- 완료 기준: 토픽 이름뿐 아니라 실제 메시지·발행기·timestamp·TF 변환을 확인한다. 정지 명령 후 실측 속도 감소가 관측되며 명령 재유입 경로를 확인한다.

### 4주차 — 두 로봇 분리와 기반 인계

- 1~2일: 모델명·namespace·프레임·초기 위치를 launch 인자로 분리한다. 임시 URDF 파일 충돌을 제거하고 `ax_simulation`·공통 bringup 구성을 정리한다.
- 3~4일: `robot_1`, `robot_2`를 동시에 생성한다. 한쪽에만 주행·팔·집게 명령을 보내 반대쪽 상태를 관측하고 B/C/D와 연결한다.
- 5일: TC-01 기반 검증과 다른 팀원 환경 실행을 수행한다. 최종 명령 차단 경로와 적재물 유지 정책을 공동 확정한다.
- 산출물: 두 대 launch, 로봇별 파라미터, 실행 안내, TC-01 증거.
- 완료 기준: 명령·센서·이동 TF 혼선이 없고 두 로봇을 독립 제어한다. 기본 주행 인계와 안전 차단 경로 검증을 마친다.

### 5주차 — Task Executor와 가짜 서버 계약 테스트

- 1~2일: `ax_task_executor`를 생성하고 `ExecuteTransportTask` 서버, goal 검증, 실행 단계·피드백·결과를 구현한다.
- 3~4일: D 주행·C 조작의 가짜 Action 서버를 연결한다. 성공·거절·실패·지연·취소 응답을 주입하고, 로봇별 동시 goal 수락 정책과 `assignment_id` 검사를 구현한다.
- 5일: 운반 상태 전이 전체를 실제 주행 없이 계약 테스트한다.
- 산출물: 실행기 기본 노드, 가짜 서버, 상태 전이표·계약 테스트.
- 완료 기준: 정상 목표가 정해진 순서대로 진행되고 잘못된 로봇·중복 실행·이전 배정 결과를 차단한다. 액션 결과와 전역 상태의 `TIMED_OUT` 대응을 D와 확정한다.

### 6주차 — 안전 차단과 취소 처리

- 1~2일: B의 `SafetyState`를 받아 감속·정지·UNKNOWN·오래된 상태를 처리한다. 정지 요청·정지 중·정지 완료를 구분하여 `actuation_state`를 발행한다.
- 3~4일: 이동·집기·놓기 단계별 취소와 하위 Action 취소 확인을 구현한다. 명령 차단 중 새 명령이 들어오는 경우, 물체를 든 상태의 정지·유지 동작을 검증한다.
- 5일: B/C/D와 정지 지연을 측정하고 센서 복구 후 재개 조건을 확인한다.
- 산출물: 안전 게이트, 취소 처리, `actuation_state`, 정지 측정표.
- 완료 기준: 정지 요청만으로 `STOPPED`를 보고하지 않고 합의된 상태 피드백으로 확인한다. 센서 불확실 상태에서 시간초과만으로 재개하지 않는다. 취소 미확인 시 새 작업을 실행하지 않는다.

### 7주차 — 실제 주행·조작 연결과 오류 전파

- 1~2일: 가짜 서버를 D 주행·C 조작 서버로 교체하고 pickup·dropoff pose 및 프레임 변환 조건을 확인한다.
- 3~4일: 인식 실패·집기 실패·낙하·주행 시간초과를 주입한다. C의 재시도 횟수·`object_held`를 받아 A의 결과에 반영하고 D에 보고한다.
- 5일: `PAUSED → RECOVERING`과 단계별 재개 조건을 검증한다.
- 산출물: 실제 Action 연결, 오류 처리표, 재개 조건표, 실패 시나리오 기록.
- 완료 기준: C 재시도와 A 재시도가 겹쳐 무제한 반복되지 않는다. 불확실한 적재 상태를 성공·비적재로 간주하지 않고 중단·보고한다.

### 8주차 — 한 대 전체 운반 완료

- 1~2일: 인식·집기·이동·놓기의 전체 흐름에서 실패 원인을 정리하고 우선 결함을 수정한다.
- 3~4일: 한 대 정상 운반과 센서 끊김·집기 실패·취소 시나리오를 반복한다. 합의된 시간초과·재시도·정지 허용값을 파라미터로 정리한다.
- 5일: TC-02, TC-04, TC-05의 A 관련 결과를 팀에 공유한다.
- 산출물: 한 대 운반 실행 구성, 단계별 로그, 반복 시험 결과.
- 완료 기준: 실제 인식·조작·주행이 연결된 운반 성공을 확인하고 실패 시 안전한 종료·결과 보고를 재현한다. 가짜 서버 성공은 별도로 표시한다.

### 9주차 — 두 실행기와 재배정 연계

- 1~2일: 두 실행기를 독립 기동하고 로봇별 상태·파라미터·로그를 분리한다. D 배정 식별자와 종료 확인을 연결한다.
- 3~4일: 두 대 동시 운반, 중복 goal, 취소 직후 새 배정, 늦게 도착한 이전 결과를 시험한다.
- 5일: D/C와 기존 실행 종료·적재 확인·재배정 가능 상태를 검토한다.
- 산출물: 두 실행기 bringup, 배정 세대 검사, TC-03·TC-08 기록.
- 완료 기준: 동일 배정이 중복 실행되지 않고 이전 결과가 현재 작업을 덮지 않는다. A는 재배정을 직접 수행하지 않고 실행 종료·적재 상태를 D에 제공한다.

### 10주차 — 통로·교행 통합

- 1~2일: D 주행의 통로 대기·진입·해제와 A 실행 상태를 연결하고 통로 대기 중 취소·정지 동작을 정의한다.
- 3~4일: 마주침, 통로 내 센서·위치 상실, 통로 점유 중 작업 취소를 B/D와 시험한다.
- 5일: TC-06·TC-07·TC-08 관련 결함을 수정하고 두 대 규칙 기반 기준선을 저장한다.
- 산출물: 통로 대기·취소 연계, 두 대 기준선 로그, 통합 결과표.
- 완료 기준: A의 취소·시간초과가 D의 통로 점유를 임의 해제하지 않는다. 불확실하면 정지·보류하며 신규 실행은 D 허가 체계를 따른다.

### 11주차 — 제어 이상 탐지 데이터

- 1~2일: `ax_control_ml`과 로거를 구성한다. 목표·실제 속도, 관절 오차, 명령 지연 등 실제 확보 가능한 특징을 확정한다. effort 등 없는 피드백은 결측·미지원으로 표시한다.
- 3~4일: 정상 주행·조작 데이터를 수집하고 시뮬레이션에서 미끄러짐·관절 떨림·지연을 주입한다. 시나리오·episode·seed·모델 버전을 함께 기록한다.
- 5일: 에피소드 단위 학습·검증·시험 분할과 오류 라벨 품질을 확인한다.
- 산출물: 특징 스키마, 데이터셋, 오류 주입 도구, 분할 목록.
- 완료 기준: 데이터 수집을 재현할 수 있고 같은 에피소드가 학습·시험에 중복되지 않는다. 안전 이벤트와 ML 라벨을 구분한다.

### 12주차 — Isolation Forest와 진단 연결

- 1~2일: 정상 학습 데이터로 Isolation Forest를 학습하고 검증 데이터로 임계값을 선택한다. 시험 데이터로 탐지율·오탐률·지연을 측정한다.
- 3~4일: 이상 점수·플래그·모델 가용성 출력을 연결한다. 모델 미존재·로드 실패·입력 결측·추론 지연 시 규칙 기반 제어 유지를 검증한다.
- 5일: 기존 규칙 진단과 비교하고 모델 채택·보류 근거를 기록한다.
- 산출물: 버전이 있는 모델, 추론 노드, 평가표, TC-11 결과.
- 완료 기준: 모델 오류가 운반 기본 기능이나 안전 차단을 막지 않는다. ML의 직접 정지 권한을 추가하지 않고 진단 보조로 유지한다.

### 13주차 — 중앙 Agent ADVISORY 지원

- 1~2일: D가 FleetSnapshot에 반영할 실행 단계·정지 상태·적재 정보의 출처·갱신 시각을 정리한다. A 제공 상태와 C 소유 상태의 경계를 유지한다.
- 3~4일: Agent 제안과 실제 로봇 실행 결과를 작업·배정 ID로 연결하여 기록한다. Agent가 정지·취소·작업 실행 경로를 우회하지 않는지 D와 확인한다.
- 5일: ADVISORY 제안과 기본 운영 결과를 비교할 로그를 전달한다.
- 산출물: 실행 상태 연계, 제안·결과 추적 로그, TC-09 지원 기록.
- 완료 기준: ADVISORY 제안은 실제 실행을 변경하지 않고, 오래된 상태를 기반으로 한 제안의 검증에 필요한 정보가 D에 제공된다.

### 14주차 — 제한적 ASSISTED 통합 지원

- 1~2일: 앞선 통합 검증을 통과한 경우에만 D 검증 후 반영되는 배정·재시도·재배정 시나리오를 연결한다.
- 3~4일: AI 응답 지연·잘못된 로봇 지정·오래된 snapshot·중복 제안을 주입한다. A의 배정 검사·취소 확인·안전 차단이 유지되는지 검증한다.
- 5일: TC-10·TC-11 결과를 정리하고 규칙 기반 복귀를 시연한다.
- 산출물: AI 개입 시나리오 결과, 복귀 기록, 잔여 결함 목록.
- 완료 기준: AI 오류가 기존 안전 불변조건을 훼손하지 않는다. 선행 검증 미완료 시 ADVISORY를 유지하고 ASSISTED를 완료로 표시하지 않는다.

### 15주차 — 반복 검증과 결함 수정

- 1~2일: 설정·seed·시험 목록을 고정하고 기준선·AI 적용 시험을 수행한다.
- 3~4일: 단계별 시간, 정지 지연, 실패·취소·복구 결과, ML 탐지·오탐을 집계한다. 중복 실행·정지 실패 등 핵심 결함을 우선 수정한다.
- 5일: 변경 영향이 있는 시험을 다시 수행하고 미해결 항목·제약을 기록한다.
- 산출물: 반복 시험 결과, 원인별 결함표, 수정 검증 기록.
- 완료 기준: A 관련 TC-01~TC-12의 참여 결과가 추적 가능하고, 성공·실패를 누락 없이 보고한다. 실측 결과 없이 개선을 주장하지 않는다.

### 16주차 — 최종 시연과 인계

- 1~2일: 다른 팀원 환경에서 의존성 설치·빌드·실행·두 대 운반을 재현하고 실행 안내를 수정한다.
- 3~4일: 정상 운반, 안전 정지, 실패·취소, 규칙 기반 복귀 시연을 준비한다. 코드·설정·모델·데이터 버전과 증거 경로를 정리한다.
- 5일: 최종 시연·결과 제출·인계를 수행하고 미해결 이슈를 담당자와 함께 남긴다.
- 산출물: 인계 문서, 실행·검증 명령, 최종 결과표, 시연 자료, 알려진 제약.
- 완료 기준: 다른 환경에서 재현되고 실행 코드와 문서가 일치한다. 최종 결과에 개발용 모델 여부·정확도 제한·미지원 기능을 명시한다.

## 7. 검증량과 수치 확정 계획

아래 횟수는 원문 요구사항이 아닌 일정 산정을 위한 최소 시험안이다. 실제 성능 평가는 팀이 시나리오와 목표값을 합의하여 확정한다.

| 검증 | 제안 시험량·방법 | 확정 시점 |
|---|---|---|
| 관절 추종 | 제어 관절별 가동 범위 내 대표 목표 3개, 각 3회, 오차·정착시간 측정 | 2주 |
| 두 대 분리 | 각 로봇에 주행·팔·집게 명령을 개별 발행하고 상대 로봇 상태 관측 | 4주 |
| 안전·취소 | 이동·집기·놓기 각 단계에서 정지·취소, 각 3회 | 6~8주 |
| 한 대 운반 | 서로 다른 물체 배치 3조건, 조건별 3회 | 8주 |
| 두 대 통합 | 정상 동시 실행·마주침·취소 후 재배정·통로 위치 상실, 각 3회 | 10주 |
| ML | 에피소드 분리 시험, 탐지율·오탐률·추론 및 탐지 지연 보고 | 11~12주 |
| 최종 비교 | 기준선·AI에 동일한 3개 이상 seed, seed별 3회 | 15주 이전 |

정지 지연·정착 오차·센서 유효시간·Action 시간초과는 측정 시작과 끝, 기준 시계, 허용값을 함께 기록한다. 안전 정지시간은 시스템 시계 지연도 확인하고, 운반시간은 동일 시뮬레이션 시간 기준으로 비교한다. 기존 임시 오차 기준을 최종 요구 사양으로 자동 채택하지 않는다.

## 9. A 최종 인계 체크리스트

- [ ] 다른 팀원 환경의 빌드·실행·검증 재현 결과가 있다.
