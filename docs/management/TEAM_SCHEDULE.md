# AX 팀 공통 일정·기능별 업무 분담

> A~E는 기능 영역이다. 번호별 담당은 1 이종수·2 양현승·3 김성민·4 엄승연으로 확정했다. 시작일·기간은 미정이다.
> 전체 신규 개발 범위를 기준으로 작업을 나누며 현재 진척 때문에 개인 업무량을 줄이거나 늘리지 않는다.
> 기존 A 단독 16주 일정은 이 문서로 통합한다. 일정·시험 요구는 구현 완료나 시험 통과가 아니다.
> 기준: [본설계](../design/DETAILED_DESIGN.md). 이전 구현 기록은 커밋 `4f85007` 이력을 참조한다(아래 "이전 구현 기록").

## 일정 운영 원칙

전체 일정·A1~E4 산출물·개인 분담·의존성·검증을 이 문서에서 같은 작업 ID로 관리한다.
기능 A~E 전체를 개인 한 명씩 맡기지 않고 같은 번호의 세부 작업을 한 사람이 맡는다.
담당자는 아래 표에 표시하며 가용 시간·산정 기간·일자는 확정 후 작업 ID에 붙여 관리한다. 중복 개인 일정 문서를 만들지 않는다.

개발 중 단위·계약·모의 시험과 조기 통합을 병행한다. 충분한 후반 검증 기간을 확보하고
결함 수정·회귀·재시험을 명시적 작업으로 계산한다. 기존 16주를 새 범위의 완료 약속으로 쓰지 않는다.
실제 달력과 총기간은 네 사람의 가용 시간·작업 추정·장비 처리량을 확인한 뒤 확정한다.

연결되는 인터페이스·통합 시험은 생산자와 소비자가 공동 확인한다. 기간·현재 진척에 따른 재분배는 하지 않는다.

## 읽는 방법과 난이도

인터페이스의 T는 Topic, S는 Service, A는 Action이다. 지속 관측은 T, 짧은 요청·응답은
S, 진행 상태·취소가 필요한 장시간 실행은 A로 나눈다. 같은 기능을 세 방식으로 중복 구현하지 않는다.
아래의 상태·요청 이름은 계약의 의미를 나타낸다. 정확한 경로·타입·필드는 공통 계약에서 확정하며,
이 표가 새 ROS 인터페이스의 구현 완료를 뜻하지 않는다.

| 난이도 | 판단 기준 |
|---|---|
| 중 | 입력·출력과 실패 조건이 비교적 명확하며, 단일 모듈 중심으로 시험 가능 |
| 상 | 좌표·물리·인식·계획 또는 여러 노드의 비동기 처리를 함께 검증해야 함 |
| 최상 | 안전 우선순위, 취소 경합, 분산 상태·복구·영속성을 함께 다루며 통합 실패 영향이 큼 |

난이도는 개발·시험 복잡도의 상대 평가다. 소요일·인원 수의 환산값이 아니며,
모델 선정·데이터 품질·팀 숙련도가 정해진 뒤 일정으로 산정한다.
의존성은 통합 검증에 필요한 선행 결과다. 계약과 모의 입력이 있으면 구현은 병행할 수 있다.

## 공통 선행 작업 K0 — 계약과 시험 기준

20개 기능에 중복 계산하지 않는 공통 작업이다. 해당 상태의 소유 영역이 의미를 정의하고,
인터페이스별 생산자와 소비자가 함께 작성·승인한다(본설계 11절). K0는 네 사람의 공동 작업이며 각자 맡은 생산자·소비자 계약과 모의 상대·시험을 제공한다. 별도 공통 조정 담당은 아직 정하지 않았다.

| 산출물 | 포함 내용 |
|---|---|
| 인터페이스 명세·공유 타입 | 로봇·작업·물체·실행 ID, 단위·좌표계, Topic QoS·최신성, Service 오류, Action 취소·Result·Feedback |
| 권한·실행 계약 | 발신자 인증, 상태 소유권, 단계별 실행 ID, 예산·lease, 보류·재시작 규칙 |
| 모의 구성 | A~E 서버·상태 발행기, 정상·만료·단절·중복·취소 입력, 실제 실행과 구분되는 시험 데이터 |
| 검증 기준 | 시나리오별 성공·실패·판정 불가, 시뮬레이션/감독 시계, 독립 관측 로그와 재현 조건 |

공유 메시지 패키지의 도입·타입 확정도 이 범위다. 원장 형식이나 모든 임계값이 정해질 때까지
전체 구현을 기다리지는 않되, 서로 연결하는 계약은 소비자와 합의한 버전으로 고정한다.

## 배정 후 협업·검증 기준

기능마다 4개로 나눈 것은 업무 경계를 드러내기 위한 것이며, 행 수가 같다고 공수가 같지는 않다.
다음 큰 작업은 현재 담당을 유지하되 내부 산출물로 나누어 진척·검증을 관리한다.

| 큰 작업 | 나눌 수 있는 내부 산출물 | 유지할 통합 책임 |
|---|---|---|
| A4 | 관절 보호 / 최종 구동 게이트·정지 확인 / 프로세스·시계 감독 | 정지 우선순위와 실제 구동 조건 |
| C4 | 조작 실행 / 보유·해제 결과 / lease·시도 보고·취소 | 물리 시도와 Action 결과의 일치 |
| D2 | 작업 배정 / 인계 단계 / 그룹 물체 상태·완료 | 그룹 단계 전이 |
| D4 | 인증·제안 검증 / 보류·격리 / 예산·실행 원장·복원 | 승인 권한·예산·영속 상태의 일관성 |

번호별 개인 배정은 위 표로 확정했다. 행 수가 같다고 공수·난도가 같은 것은 아니므로
큰 작업의 세부 추정·공동 통합 시험 시간을 공통 일정에서 관리한다. Topic·Service·Action은 각 기능에
적합한 방식을 사용하고 체험을 위한 중복 인터페이스를 추가하지 않는다. 기간은 미정이며 아래 단계·관문에서 검증 기간을 별도 확보한다.

이 표의 완료 확인은 앞으로 수행할 검증 요구다. 현재 작업 완료·G1 충족을 뜻하지 않는다.

## 공통 시험 산출물과 범위 보존

K0에 독립 시험 관측기·대조기를 포함한다. 각 실행 담당 A3·C4·D1이 관측 연결점을 제공하고,
각 기능의 관측 연결점은 해당 작업자가 책임지고, 공통 통합 시험의 조정 담당은 별도 지정한다. 시험 대상 원장과 독립적으로 부착 전이·물리 시도·
Nav2 goal UUID를 수집하며, 누락은 판정 불가로 처리한다. 기준은 [본문 13.1절](../design/DETAILED_DESIGN.md#131-자동-운영agent영속-복원-시나리오)이다.

본설계 DEC-12·4절의 ML·DL은 제외하지 않는다. A4 제어 이상, B2 위치 이상, B3 환경 YOLO,
C1 물체 YOLO, C3 집기 성공률, D2 ETA에 데이터·학습·평가를 포함한다.
각 모델의 오류·결측 시 규칙 기준선 복귀는 TC-11, 비교는 TC-12와 본설계 10절을 따른다.
E-14는 LLM 효과 평가이므로 이들 모델별 품질 시험을 대신하지 않는다.

A3↔C4와 D4↔E3는 구현 완료의 상호 선행 조건이 아니라 K0에서 함께 고정할 계약이다.
각각 모의 상대와 개발한 뒤 통합한다. 표의 관련 시험은 추적 기준이며 모델·센서·학습의
개별 검증 전체를 대체하지 않는다. 일정 소유권은 [본설계 12절](../design/DETAILED_DESIGN.md#12-팀-공통-일정과-업무-배정)을 따른다.

## 공통 단계·의존성과 검증 기간

단계 P1~P7은 상대 순서이며 기간이 아니다. 데이터·ML·모의 Agent 작업은 계약 이후 병행할 수 있다.
최종 검증 P6·수정/재시험 P7을 독립 일정으로 확보하고 기능 추가 때문에 자동 축소하지 않는다.
기간 산정 시 단위/계약/조기 통합 시험은 각 기능 공수에 포함하고 P6/P7 공수와 중복 계산하지 않는다.
